# BDD 需求文档 — 黄金政策周期监测模块

> 面向个人黄金投资者的金价与美联储利率周期关联监测功能

---

## 一、Epic Stories

### Epic 1：黄金宏观状态实时感知
为个人黄金投资者提供金价、联邦基金利率、美债收益率等核心宏观指标的月度快照，让用户在一个页面上一目了然地看到当前市场状态及其近12个月走势，辅助判断黄金的估值高低。

### Epic 2：美联储政策周期识别与标注
将1996年至今的历史月份按美联储政策阶段（加息周期 / 降息周期 / 利率平台）进行划分和标注，新的政策周期由系统根据联邦基金利率变动方向自动判定，但切换边界需用户审核确认后方可生效。

### Epic 3：历史周期回溯与学习
以政策周期为单位组织全部历史月度数据，用户可点击任一周期查看该周期内每个月的完整指标明细，用于复盘利率与金价在不同政策环境下的联动规律。

### Epic 4：数据自动维护与质量保障
每月1号自动刷新上月完整数据并存入本地；手动刷新提供一次主动获取能力；所有新进入的数据都要与已存储值做一致性校验，发现差异时提示用户确认。

---

## 二、User Stories

### US-01：查看当前黄金宏观状态卡片

> **As a** 个人黄金投资者
> **I want to** 在进入黄金页面时，看到当前月份的7个核心宏观指标卡片，每个卡片同时显示当前值和近12个月迷你走势图
> **So that** 我能快速判断金价在当前利率环境下的大致位置和趋势方向

#### BDD 验收用例

```gherkin
Feature: 当前状态页面展示

  Scenario: 用户首次进入黄金当前状态tab
    Given 本地数据表中已存在至少一个月的历史数据
    When 用户点击左侧"黄金"菜单项并停留在当前状态tab
    Then 页面左上角应显示当前月份所属的政策周期名称
    And 页面主体应展示7张指标卡片，每张卡片包含指标名称、当前值、单位、近12个月迷你折线图
    And 若迷你折线覆盖的月份不足12个月，则按实际可用月数展示

  Scenario: 当前月份数据在本地尚未存储
    Given 本地数据表最新月份早于当前月份
    When 用户进入黄金当前状态tab
    Then 页面应提示"本月数据尚未更新，是否立即刷新"
    And 已存储的最新月份数据正常展示为当前快照

  Scenario: 2003年之前的历史月份缺少实际利率数据
    Given 当前选中的是2003年之前的某个月份
    When 页面加载该月份指标
    Then 10年期TIPS实际利率卡片显示"N/A"
    And 该卡片下方显示提示文字"TIPS数据自2003年起可用"
```

> **As a** 个人黄金投资者

### US-03：手动刷新当前数据

> **As a** 个人黄金投资者
> **I want to** 在当前状态页面点击"刷新"按钮，主动获取最新已发布月份数据
> **So that** 当我发现 scheduler 每月1号自动刷新没跑（服务未启动）时，能手动补拉最新月

#### BDD 验收用例

```gherkin
Feature: 手动刷新数据

  # target_month 规则:
  #   scheduler 每月1号自动刷新 → target = 上月  (2026-11-01 → target=2026-10)
  #   manual 手动刷新           → target = 上月  (同上，拉取最新已发布月)
  #   当月数据(2026-11)尚未发布 → not_published，保留上月快照

  Scenario: 手动刷新拉取上月数据成功写入
    Given 本地最新数据月份为2026-09
    And 当前日期为 2026-11-13 (10月数据已发布)
    When 用户点击"手动刷新"按钮
    And 大模型成功返回2026-10的7个指标值
    Then 页面展示应立即更新为2026-10的数据
    And DuckDB gold_monthly 中新增一条2026-10记录
    And refresh_log 写入 source=manual, target=2026-10, action=insert
    And 若自动判定出新政策周期则进入待审核状态

  Scenario: scheduler 每月1号自动刷新上月
    Given FastAPI serve 已启动 (scheduler lifespan 已注册)
    And 当前日期为 2026-12-01
    And DuckDB gold_monthly 最新为2026-10
    When scheduler 触发每日 08:00 / 18:00 检查
    And today.day == 1
    Then 自动调用 trigger_refresh(source="scheduler")
    And target_month = "2026-11" (上月)
    And LLM 返回已发布数据后自动写入 gold_monthly
    And refresh_log 写入 source=scheduler, action=insert

  Scenario: scheduler 未启动导致月数据缺失, 手动刷新补拉
    Given 本月1-12号 serve 未启动
    And DuckDB gold_monthly 最新为2026-09
    When 用户首次启动 serve 并点击"手动刷新"
    Then trigger_refresh(source="manual") 拉取 target=2026-10
    And 若 10月数据已发布 → 写入 gold_monthly
    And 若 11月数据已发布 → 再拉一次 target=2026-11 写入
    And 页面展示最新已发布月

  Scenario: 大模型返回的数据与本地已存储数据存在差异
    Given 本地已存储2026-09金价为4319
    When 用户点击刷新，大模型返回2026-09金价为4350
    Then 页面应弹出确认弹窗，展示"本地值 vs 新获取值"的对比
    And 用户确认后才覆盖本地数据
    And 用户拒绝则保留原数据不变

  Scenario: 目标月数据尚未发布 (太早或太晚)
    Given 当前日期在 2026-12-02 (11月数据可能还没发布)
    When scheduler/手动 刷新 target="2026-11"
    And LLM 返回 not_published
    Then 不写入任何数据
    And refresh_log 记录 action=not_published, success=True
    And 页面保留本地上次数据 (2026-10)
    And 刷新按钮旁显示"11月数据尚未发布，将保留10月快照"

  Scenario: 大模型获取失败或返回字段不全
    Given 用户点击刷新按钮
    And 大模型请求超时或部分字段缺失
    Then 页面顶部应显示明显的红色/橙色提示条
    And 提示条内容为"刷新失败，数据可能不是最新"
    And 保留本地上次数据显示
    And 提示条上提供"重试"按钮
```

## 三、业务/计算规则

### R1：10年期TIPS实际利率计算
> 10年期TIPS实际利率 = 10年期美债名义利率 − 10年期盈亏平衡通胀率 BEI
>
> 说明：名义利率与 BEI 同期可得时按此公式计算；若 BEI 缺失（2003 年之前），则该月实际利率记为 N/A。

### R2：金价环比涨跌计算
> 金价环比涨跌 = (本月金价 − 上月金价) ÷ 上月金价 × 100%
>
> 结果保留两位小数，正为上涨（绿色），负为下跌（红色）。

### R3：利率月度变动计算
> 政策利率月度变动 = 本月联邦基金利率 − 上月联邦基金利率（单位：pct 点）
> 实际利率月度变动 = 本月实际利率 − 上月实际利率（单位：pct 点）
>
> 结果保留两位小数，正为上升（绿色），负为下降（红色）。

### R4：政策周期自动判定规则（用于未来新周期）
> 判定粒度为月度。当满足以下任一条件时，标记一个新周期的起点：
>
> - 加息周期起点：连续两个月联邦基金利率上升幅度均 > 0.05 pct 点，且之前处于降息或平台期
> - 降息周期起点：连续两个月联邦基金利率下降幅度均 > 0.05 pct 点，且之前处于加息或平台期
> - 平台期起点：连续两个月联邦基金利率变动幅度均 ≤ 0.05 pct 点，且之前处于加息或降息周期
>
> 每个周期的名称建议格式：`起始月 ~ 至今/结束月  （加息周期 / 降息周期 / 利率平台）`
>
> 注：自动识别出的新周期进入"待审核"状态，用户确认后方可正式生效。

### R5：数据刷新一致性校验
> 每次刷新获得新数据后，对每个已存在月份执行以下校验：
>
> - 若该月在本地尚不存在：直接入库，记录为"新增"
> - 若该月已在本地存储且所有字段值一致：无操作，提示无需更新
> - 若该月已在本地存储但至少一个字段值有差异：弹出确认，展示各字段"本地值 vs 新值"，用户确认后覆盖，拒绝则保留原值

### R6：数据版本策略
> 月度数据表仅保留每个月份的最新值，刷新时直接覆盖，不保留历史修订版本。

### R7：定时触发时间
> 每月1号触发自动刷新，拉取上一个自然月的完整数据。

### R8：5大驱动指标的利多/利空判断规则
> 系统维护 5 个黄金驱动指标，每个指标由 LLM 综合判断对金价的方向性影响：
>
> | # | 指标 key | 名称 | 核心驱动因子 | 利多条件 | 利空条件 |
> |---|----------|------|-------------|---------|---------|
> | 1 | `ffr_drivers` | 增长与就业（FFR路径） | 非农、失业率、平均时薪、ISM制造业/服务业PMI、GDP | 数据走弱→降息预期升温→利空实际利率/美元→利多黄金 | 数据强劲→加息/高利率维持→利多实际利率/美元→利空黄金 |
> | 2 | `bei_drivers` | 通胀预期（BEI） | 核心PCE、CPI、PPI、达拉斯联储trimmed-mean PCE | 通胀黏性/超预期→降息空间压缩、抗通胀属性凸显→利多黄金 | 通胀回落至锚附近→实际利率走升、抗通胀需求减弱→利空黄金 |
> | 3 | `usd_fx` | 美元与汇率 | 广义贸易加权美元指数(Broad)、人民币汇率、DXY | 美元走弱→以美元计价的黄金相对便宜→利多；⚠️DXY若由欧元单边行情驱动则降档扣分 | 美元走强→黄金承压→利空 |
> | 4 | `tail_risk` | 尾部风险溢价 | 地缘冲突、银行风险、美债流动性、美国债务/财政担忧 | 风险发酵→避险需求+去美元化→利多黄金 | 风险缓和→避险回落→利空黄金 |
> | 5 | `physical_flow` | 实物与资金流 | 央行购金、黄金ETF持仓、COMEX/上期所库存、沪金-伦敦金价差、WGC月度央行净购金、各国储备报告 | 持续大额净买入/库存下降→利多黄金 | 购金放缓/减持/库存上升→利空黄金 |
>
> 每个指标判断结果包含：`judgment`(bullish/bearish/neutral)、`confidence`(0~1)、`summary`(简述)、`details`(完整分析)。

### R9：指标分析提示词可配置
> 每个指标的 LLM 系统提示词与用户提示词存储在 `gold_signal_prompt` 表中，用户可通过 Web 界面查看和修改。修改后下次刷新生效。

### R10：指标自动刷新策略
> - 每周一凌晨自动批量刷新全部 5 个指标（每个指标单独调用一次 LLM）。
> - 支持手动刷新单个指标。
> - 刷新结果写入 `gold_signal` 历史表，保留全部历史记录（不覆盖），支持事后回看。
> - 每条记录含 `confidence` 可信度字段（0~1），由 LLM 自评或由用户事后标记。

### R11：FOMC 议息会议
> - 提供"更新FOMC日程"按钮，由用户手动触发，调用预配置提示词向 LLM 查询未来 FOMC 议息会议时间表。
> - LLM 返回的会议列表写入 `gold_fomc` 表（会议日期、标题、备注）。
> - 当前状态页面显眼处显示"下一次 FOMC 会议"日期（取未来最近的一条）。

## 三-B、扩展 Epic Stories（V2）

### Epic 5：当前政策周期内利率走势可视化
在当前状态 tab 的 7 张指标卡片下方，新增一条趋势图区域，展示**当前政策周期内**联邦基金利率(%)、10Y名义利率(%)、10Y实际利率(%)三条折线，便于用户直观看到当前周期的利率演变。

### Epic 6：5 大黄金驱动指标的 LLM 分析
系统维护 5 个影响金价的核心驱动指标（增长与就业、通胀预期、美元与汇率、尾部风险、实物与资金流），每个指标由可编辑的提示词驱动 LLM 输出利多/利空判断、可信度和分析摘要。每周一凌晨批量自动刷新，支持手动单指标刷新，全部结果入历史表供回看。

### Epic 7：FOMC 议息会议日程展示
支持手动触发 LLM 获取未来 FOMC 议息会议时间表，存入本地表，并在当前状态页面显眼处展示下一次会议日期。

### Epic 8：黄金日线行情实时监控（V3）
在"黄金"模块下新增独立的"日线行情"Tab，展示上期所黄金主力连续（AU0）的完整日线 OHLCV 历史和当日实时最新价。后端定时任务每日 8:00/18:00 自动从 akshare 拉取并 upsert 到 MySQL `vibe.gold_daily_bar`；前端提供手动刷新按钮。价格口径为人民币/克（上期所期货），同时换算并展示美元/盎司参考价。数据源为 akshare `futures_main_sina(symbol="AU0")`，在中国大陆 IP 下稳定可用（Yahoo Finance 自 2021-11-01 起对大陆 IP 全域名封，不可用）。

## 五-B、扩展数据管理规则（V2）

### D6：gold_signal 表（指标分析历史）
> 主键 `signal_id`(UUID)，字段：`indicator_key`、`judgment`(bullish/bearish/neutral)、`confidence`(0~1)、`summary`、`details`、`source`(manual/scheduled)、`created_at`。
> 不覆盖，每次刷新新增一条；用户可修正 `confidence`。

### D7：gold_signal_prompt 表（指标提示词）
> 主键 `indicator_key`，字段：`system_prompt`、`user_prompt`、`updated_at`。
> 首次部署时为 5 个指标写入默认提示词。

### D8：gold_fomc 表（FOMC会议日程）
> 主键 `meeting_id`(UUID)，字段：`meeting_date`、`title`、`notes`、`source`、`updated_at`。
> 手动更新时清空未来会议记录再写入。

### D9：gold_daily_bar 表（黄金日线行情，已在 vibe MySQL 库）

> 存储上期所黄金主力连续（AU0）的日线 OHLCV 历史 + 当日实时价。数据源为 **akshare `futures_main_sina(symbol="AU0")`**（中国大陆 IP 下唯一稳定可用方案，Yahoo 系自 2021-11-01 起被大陆 IP 全域名封禁）。
>
> 表结构（已在 vibe MySQL 库执行，`scripts/gold_create_tables.py`）：
>
> ```sql
> CREATE TABLE gold_daily_bar (
>     trade_date          DATE NOT NULL                           COMMENT '交易日',
>     symbol              VARCHAR(16) NOT NULL DEFAULT 'AU0'      COMMENT 'AU0=上期所黄金主力连续, AU9999=现货',
>     exchange            VARCHAR(8)  NOT NULL DEFAULT 'SHFE',
>     open                DOUBLE NOT NULL                         COMMENT '开盘价 人民币/克',
>     high                DOUBLE NOT NULL                         COMMENT '最高价 人民币/克',
>     low                 DOUBLE NOT NULL                         COMMENT '最低价 人民币/克',
>     close               DOUBLE NOT NULL                         COMMENT '收盘价 人民币/克',
>     prev_close          DOUBLE          DEFAULT NULL            COMMENT '前一交易日收盘价 (自动推导)',
>     volume              BIGINT          DEFAULT NULL            COMMENT '成交量 手',
>     open_interest       BIGINT          DEFAULT NULL            COMMENT '持仓量 手',
>     settlement          DOUBLE          DEFAULT NULL            COMMENT '动态结算价 (akshare 返回)',
>     change_amt          DOUBLE          DEFAULT NULL            COMMENT '涨跌额 = close - prev_close',
>     change_pct          DOUBLE          DEFAULT NULL            COMMENT '涨跌幅 %',
>     fx_rate_cny_usd     DOUBLE          DEFAULT NULL            COMMENT '当日 USD/CNY 汇率 (换算用)',
>     price_usd_per_oz    DOUBLE          DEFAULT NULL            COMMENT '美元/盎司参考价 = close * 31.1035 / fx_rate',
>     is_interday         TINYINT(1) NOT NULL DEFAULT 0           COMMENT '0=已收盘 1=盘中实时',
>     source              VARCHAR(32) NOT NULL DEFAULT 'akshare.futures_main_sina',
>     fetched_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
>     updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
>     PRIMARY KEY (trade_date, symbol),
>     KEY idx_gold_daily_date (trade_date),
>     KEY idx_gold_daily_symbol (symbol)
> ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='黄金日线行情 (SHFE AU0, 人民币/克 + USD/oz 参考)';
> ```
>
> Upsert 规则：按 `(trade_date, symbol)` 主键 INSERT ON DUPLICATE KEY UPDATE 幂等写入。`prev_close` / `change_amt` / `change_pct` / `price_usd_per_oz` 四个字段**由后端 upsert 时自动计算并填入**，不直接信任 akshare 返回。

### D10：gold_daily_refresh_log 表（黄金日线拉取日志）

> 每次定时任务或手动刷新执行完后写一条，用于审计和失败排查。
>
> ```sql
> CREATE TABLE gold_daily_refresh_log (
>     log_id              BIGINT NOT NULL AUTO_INCREMENT,
>     refresh_type        VARCHAR(16) NOT NULL                      COMMENT 'scheduled / manual / init',
>     fetch_symbol        VARCHAR(16) NOT NULL DEFAULT 'AU0',
>     rows_fetched        INT NOT NULL DEFAULT 0,
>     rows_inserted       INT NOT NULL DEFAULT 0,
>     rows_updated        INT NOT NULL DEFAULT 0,
>     latest_trade_date   DATE            DEFAULT NULL,
>     is_interday         TINYINT(1) NOT NULL DEFAULT 0,
>     source              VARCHAR(32) NOT NULL DEFAULT 'akshare.futures_main_sina',
>     status              VARCHAR(16) NOT NULL DEFAULT 'ok'         COMMENT 'ok / partial / failed',
>     error_msg           VARCHAR(512)    DEFAULT NULL,
>     fetched_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
>     PRIMARY KEY (log_id),
>     KEY idx_refresh_log_date (fetched_at),
>     KEY idx_refresh_log_type (refresh_type)
> ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='黄金日线拉取日志';
> ```

### R12：黄金日线定时刷新规则
> 后端 celery/scheduler 定时任务：
> - **每日 08:00**：拉取前一交易日收盘数据（覆盖日盘 + 夜盘）
> - **每日 18:00**：盘中补拉（日盘已收盘，夜盘刚开盘）
> - 手动刷新：前端按钮触发，走相同 upsert 链路，`refresh_type='manual'`
> - 首次全量初始化：`refresh_type='init'`，start_date="20200101"
>
> 数据源固定为 akshare `futures_main_sina(symbol="AU0")`，**不做多源 fallback**（经实测 Yahoo 系在中国大陆 IP 下全域名封禁，Eastmoney secid 格式不稳定，均不可靠）。
>
> 刷新频率上限：单日（自然日）内同一 symbol 最多刷新 10 次（防止用户疯狂点击触发 akshare 限流）。

## 五、数据管理规则

### D1：数据表结构
系统维护两张本地数据表：
- **月度指标表**：主键为 (月份)，存储7个核心指标值 + BEI原始值 + 更新时间戳
- **政策周期表**：主键为 (周期ID)，存储周期名称、起止月份、周期类型（加息 / 降息 / 平台）、状态（已生效 / 待审核）

### D2：数据来源
- **历史初始数据**：首次部署时从用户提供的历史月度数据导入（覆盖1996-10 至 当前已完成月份）
- **后续增量数据**：通过大模型调用预先配置的提示词获取，每月1号自动触发、支持手动触发
- **历史政策周期**：首次部署时按用户提供的历史政策周期划分表直接导入

### D3：数据一致性保障
- 每次大模型返回数据后都执行 R5 定义的一致性校验
- 定时任务触发的数据差异在下次页面访问时提示
- 大模型调用失败或返回字段不全时，不写入数据表，仅保留原有值

### D4：数据可追溯性
虽然同一月份仅保留最新值，但每次刷新都会记录该次调用的来源摘要（成功 / 失败、返回字段完整度），供排查问题。

### D5：政策周期审核
- 自动识别的新周期默认进入"待审核"状态
- 待审核周期不参与当前状态tab的自动展示逻辑
- 用户确认后变为"已生效"，立即对当前状态和历史tab生效

## 六、业务术语表

| 术语 | 定义 |
|------|------|
| 金价（月均） | 国际金价月度平均价格，单位美元/盎司 |
| 联邦基金利率（FFR） | 美国银行间隔夜拆借的实际有效利率，是美联储货币政策的核心操作目标 |
| 名义利率 | 10年期美国国债的市场收益率，未剔除通胀预期 |
| 盈亏平衡通胀率（BEI） | 10年期名义利率与10年期TIPS收益率之差，代表市场对未来通胀的预期 |
| TIPS实际利率 | 10年期通胀保值国债（TIPS）的收益率，已剔除通胀预期；等于名义利率减BEI |
| 加息周期 | 美联储连续提高联邦基金利率的阶段，通常伴随金价承压 |
| 降息周期 | 美联储连续降低联邦基金利率的阶段，通常伴随金价上行 |
| 利率平台 | 联邦基金利率连续多月保持稳定（月度变动 ≤ 0.05 pct 点）的阶段 |
| 政策周期 | 由若干连续月份组成的区间，在该区间内美联储维持同一货币政策倾向（加息、降息或平台） |
| Sparkline | 迷你折线图，以极紧凑的空间展示一个指标的近期走势 |
| pct 点 | 百分点，利率变动的计量单位，1 pct 点 = 1% |
