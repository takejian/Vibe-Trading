## 1. Epic Story（史诗故事）

### 1.1 宏观业务目标

Vibe-Trading 是一套面向个人研究者与专业投研人员的**自然语言投资研究工作台**，覆盖全球十余个市场。它把"查资料—核数据—做研究—验策略—看组合—有限授权执行—事后复盘"整条投资研究链路收敛到同一套系统中，核心业务承诺有四条：

1. **研究结论必须有据可查**：每一个数字都能追溯到某次实际取得的行情或研究资料，身份不可错（A 股与港股同名公司不得混淆），数字、币种、日期、来源四要素齐备。
2. **证据不足，宁可不采信**：取数失败、证据缺失、结论无据、策略历史表现不达标时，系统一律明示失败或降级，绝不拿猜测、记忆或残缺数据冒充结论。
3. **默认只读，授权才可下单，且永远故障关闭**：开箱只能研究不能交易；真实下单必须有账户主人亲自签署、范围有限、定期重签的授权书；任何无法判定的风险一律按"禁止"处理；任何人可随时一键紧急停止全部交易。
4. **把机构投研团队做成可复用的服务**：用户可召集由多个研究角色组成的"编队"（如投资委员会：多空辩论、风控复核、基金经理终裁），角色之间有严格的先后依赖与结论可信纪律。

### 1.2 角色定义

| 角色 | 业务定位 |
| --- | --- |
| 研究员 | 主要使用者。用自然语言提问、查行情、读资料、做历史回放、评测因子、管理研究目标与假设。 |
| 账户主人（授权人） | 券商账户的实际所有人。决定只读/可交易、签署授权书、可随时紧急停止、可选择逐笔人工批准。 |
| 渠道使用者 | 在 Telegram、飞书、钉钉、Slack 等聊天软件中与系统对话、接收定时研报的人；首次私聊须经配对授权。 |
| 渠道操作员 | 被授权管理一个或全部消息渠道、批准配对码、启停渠道的人；全局操作员与单渠道操作员权限隔离。 |
| 编队各研究角色 | 编队中承担特定职责的虚拟岗位（如多头研究员、空头研究员、首席风险官、基金经理）。 |
| 编队主持人 | 编队的调度岗位：匹配预设编队、统一身份基准、按依赖派活、门禁、回收失联任务、归集最终报告。 |
| 策略复核人 | 策略入库前的独立批准人；登记策略的作者与批准人不得为同一人（四眼原则，目前为提示性约束）。 |
| 运维管理员 | 预先批准编队可使用的外部数据能力、维护渠道与系统配置的管理人员。 |

### 1.4 端到端核心业务流程

**流程 A：一次投研问答**
研究员提问 → 系统先"查名"锁定标的身份（有歧义则澄清或不锁定）→ 按市场识别规则到各行情供应方按序取数（失败替补、逐只留痕）→ 研究助手逐轮分析（无进展/停滞/被审核拦截均有守护）→ 结论中每个数字核对四要素（代码、来源、币种、日期）→ 无据数字被剪裁或整份拒绝发布 → 研究卡片与全程留痕归档。

**流程 B：一个策略从想法到监控**
登记假设 → 发起历史回放取证（五道硬门：运行成功、指标齐全、有成交、净值连续无缺口）→ 证据质量评级（成交笔数、覆盖时长、成本敏感性）→ 独立复核人批准入库 → 小仓实盘前持续监控 → 证据老化 90 天转观察、180 天转失效 → 衰减信号累积触发降级/停用 → 证据充分的策略方可改编新版本。

**流程 C：授权与下单**
账户主人在工作台收到下单提案（2–4 档、全部钳制在天花板内）→ 严格真值确认后签署有限授权书 → 下单请求依次过七步门禁（授权书存在、未过期、未紧急停止、账户匹配、要素可解析、只读核对持仓、逐项约束）→ 通过后"先留存待处理标记、再发券商、再写审计、最后清标记" → 任何环节异常即拒单；紧急停止标记放置后，所有下单立即被直接拒绝，但研究只读能力不受影响。

**流程 D：编队投研**
提出研究主题 → 点名或匹配预设编队（歧义拒绝猜测）→ 主持人统一识别标的并预取基准行情 → 同层角色并行、上游成功后下游才开工（风控失败则基金经理不得在零风控下出结论）→ 每个角色的成果按产出契约验收（空稿、模拟数据、只列计划均判未达标）→ 末层决策角色汇总为可执行结论 → 归档，可重跑或仅续跑失败部分。

**流程 E：定时研报**
研究员提出定时研究意图 → 先生成提案（不创建任务）→ 用户回复"确认"后任务入档 → 按排程到点派发研究 → 研究完成后经"外发箱"向指定渠道投递（同一封只发一次、失败有限重试、系统重启补发）→ 用户在聊天软件收到与应用内一致的终态研报。

**流程 F：网页编排团队评估（M12）**
进入智能体团队编排页 → 第 1 步分两个分区：一次性展示全部内置团队预设卡片、以及仅本人可见的"我的自定义团队"（初次使用时为空）→ 选定一套内置预设或自己的团队（如投资委员会）→ 流程图呈现全部角色节点与依赖连线 → 用户经"新增角色"从角色广场已通过角色（含内置角色）中选择引入、删除角色，并临时调整角色要素（职责说明/可用分析能力/使用技能/执行时长）与协作连线（画布不提供直接创建角色入口；临时调整仅作用于本次评估或另存团队，不回写角色本体；实时校验循环依赖、孤立节点、悬空连线、无起点，不合法即高亮并禁止发起）；"使用技能"默认列出该团队预设已配置技能的并集，可通过"新增"浏览系统全部已通过技能并自由勾选追加 → 流程合法时可随时"另存为我的团队"（团队名称必填、适用场景简介选填、与本人已有团队重名则拦截改名；内置预设始终保持原样；我的团队可再次载入并原地更新、另存为新团队或删除，删除不影响历史评估快照）→ 填写评估标的与研究问题（如"当前市场环境下对 600519.SH 做多还是做空"）→ 一键发起 → 流程图上同层角色并行进入分析、上游成功后下游才开工 → 点击节点侧栏查看该角色分析过程与结论，结论按标题、列表、表格等结构化排版呈现（残缺不成表的部分降级为纯文本）→ 末层决策角色完成后默认展开做多/做空方向及理由 → 本次编排、各角色结论与最终决策作为评估快照存入"我的评估历史"，仅本人可见、长期留存；历史列表可按评估标的关键字（代码或名称片段）与发起时间起止区间组合筛选。

**流程 G：技能广场独立浏览、技能试运行与技能准入（M14）**
投资者从左侧菜单进入与"智能体团队编排""智能体（角色）"并列的独立"技能广场"页面（编排页内不再设技能广场页签）→ 页面顶部提供"技能广场"与"我的评估"两个页签 → "技能广场"页签按"内置技能"与本人"自建技能"两个分组展示全部已装配技能（名称、业务用途简介、已通过/未通过状态），每组支持按技能名称关键字检索 → 点击任一技能进入技能详情页："技能档案"页签只读或可编辑地展示业务用途简介、方法论与操作说明全文、输入要求与输出约定；"试运行"页签填写评估标的与研究问题对该技能单独发起一次试运行（标的或问题为空不得发起），成果按编队成果口径验收（空稿、只列计划、模拟数据均判不合格）；"试运行历史"页签展示本人对该技能的全部试运行记录与结论 → 投资者可从空白创建技能，或在任一已通过技能详情页点"另存为新建技能"（仅已通过技能可作模板；方法论、操作说明、输入要求、输出约定与业务用途按模板预填、可再修改，名称不预填、须全局唯一；登记派生来源，派生后独立于模板后续状态），也可经"导入 zip 技能包"入口（预留）将外部技能包导入为本人的未通过自建技能，与金融无关或要素不完整的包在导入环节即拒绝并说明原因 → 自建技能初始为"未通过"、仅创建者本人可见、可试运行、可编辑删除；该技能至少由任一投资者成功试运行一次、产出合格结论后，运维管理员在详情页才出现"放开通过"操作（审核时可查看该技能下全部人员的试运行记录）；放开通过后技能对所有投资者可见，并出现在角色配置与团队编排画布的"新增技能"可选清单中；创建者在技能通过后仍可随时编辑、编辑后保持已通过状态无需重审，删除技能须二次确认；管理员可对已通过的自建技能"取消通过" → 管理员装配的全局技能（管理员专区手动导入第三方金融技能包或一键自动同步）沿用既有准入：任一次试运行成功即全局标记"已通过"、对所有人生效，此后某次试运行失败不撤销其通过状态；新装配技能一律未通过，更新版本保留原通过状态，来源下架技能退出可选清单 → 技能被取消通过或删除后，已保存角色与自定义团队中的该技能以失效引用高亮、替换或移除前不得发起，已留存的评估快照与试运行历史原样保留、可回看 → "我的评估"页签跨技能汇总本人全部试运行记录（技能名、标的、研究问题、发起时间、终态与结论），支持按技能名、标的关键字（代码或名称片段）与发起时间起止区间组合筛选，仅本人可见、长期留存。

**流程 H：角色创建、准入与编排引入（M13）**
投资者从左侧菜单进入"智能体（角色）"页面 → 页面按内置团队预设分组展示全部内置角色（默认"已通过"、内容只读），并设"自建角色"分组与组内搜索框，支持输入角色名称关键字检索 → 投资者从空白创建角色：填写角色名称（全局唯一、重名拦截改名）、业务用途、职责提示词、可用分析能力、使用技能（仅可勾选已通过技能）与执行时长（正数），保存后角色以"未通过"状态出现在本人"自建角色"分组，其他投资者不可见 → 投资者进入角色详情页："角色档案"页签只读展示提示词、工具清单、技能清单与能力；"单独运行"页签填写评估标的与研究问题发起单角色评估（标的或问题为空不得发起），成果按编队成果口径验收（空稿、只列计划、模拟数据均判不合格）；"评估历史"页签展示本人对该角色的全部运行记录与结论 → 该角色至少由任一投资者成功单独运行一次、产出合格结论后，运维管理员在详情页才出现"放开通过"操作；审核时管理员可查看该角色下全部人员的运行记录与结论 → 管理员放开通过后，角色对所有投资者可见，并出现在团队编排画布"新增角色"可选清单中；投资者在画布引入后仍可临时调整职责、技能与时长，调整不回写角色本体 → 角色创建者可随时编辑角色（通过后编辑不撤销通过状态），删除角色须二次确认；管理员可在详情页"取消通过"：取消后角色立即退出编排可选清单，已保存自定义团队中对该角色的引用以失效高亮、替换或移除前不得发起；已留存的团队评估快照、角色单独运行记录与结论均原样保留、可回看。

## 2. User Stories（用户故事）

### M1 智能投研对话

- 作为一名**研究员**，我希望先用自然语言说出公司名或代码就能开始研究，以便不记代码后缀也能得到正确标的的分析。
- 作为一名**研究员**，我希望系统在分析 A/H 同名公司时严格按我指定的市场锁定身份，以便不会把"恒瑞医药"的 A 股和港股混为一谈。
- 作为一名**研究员**，我希望结论里的每个数字都标注来源、币种和日期，以便我能复核、敢引用。
- 作为一名**研究员**，我希望研究卡住、反复失败或长时间没有进展时系统主动终止并说明原因，以便不浪费我的时间和研究用量。
- 作为一名**研究员**，我希望长研究在篇幅将满时自动压缩且不丢失关键证据、不重复触发真实下单，以便一场复杂研究能跑完。
- 作为一名**研究员**，我希望重复问同一个确定性问题时直接引用已有答案，以便快速得到回复且不重复取数。
- 作为一名**研究员**，我希望中断的研究在系统重启后能恢复并明确标注"部分恢复"，以便我知道哪些内容可能缺失。
- 作为一名**研究员**，我希望为研究设定目标、预算与假设并让系统围绕目标自动续作有限次数，以便复杂课题有始有终。
- 作为一名**研究员**，我希望系统记住我跨会话的长期偏好与事实，以便不必每次重复背景；我也希望可以随时让它遗忘。

### M2 全球行情服务

- 作为一名**研究员**，我希望给出任意市场的代码都能被正确识别归类，以便全球市场在一个入口查询。
- 作为一名**研究员**，我希望首选行情源取不到数据时系统自动按顺序尝试下一家，以便我无需关心哪家服务临时故障。
- 作为一名**研究员**，我希望显式指定"只从某一家/只从本地库取数"时系统绝不偷偷换源，以便价格尺度差异（如托曼与美元稳定币）不会造成六位数量级错误。
- 作为一名**研究员**，我希望每只标的实际由谁供数都被记录，以便我判断数据口径是否可比。
- 作为一名**研究员**，我希望最终没取到数据的代码被明确列进"未解决"清单，以便我知道哪些标的缺失而不是被静默忽略。
- 作为一名**研究员**，我希望周线、月线始终由日线按统一口径合成，以便不同市场、不同供应方的周期数据口径一致。
- 作为一名**研究员**，我希望返回数据量过大时按等距抽样并保留最后一条，以便既能纵览全程又不会被超长回复淹没。
- 作为一名**研究员**，我希望成交量单位、复权口径被明确标注，以便不会发生"手/股"百倍差错或除权日假暴跌误判。

### M3 历史回放与业绩核算

- 作为一名**研究员**，我希望历史回放严格遵守各市场真实交易规则（T+N、涨跌停、整手、费率、保证金），以便回放结果对实盘有参考意义。
- 作为一名**研究员**，我希望回放绝不使用决策时点之后的信息（涨跌停以当根开盘实际成交价判定），以便策略表现不是"偷看未来"得来的。
- 作为一名**研究员**，我希望停牌、零价、负价、除零权益等异常数据都有明确处置，以便业绩指标不被脏数据污染出虚高夏普。
- 作为一名**研究员**，我希望混合结算币种的组合在取数前就被拒绝，以便不会得到一条尺度混乱的净值曲线。

### M4 因子库与因子审查

- 作为一名**量化研究员**，我希望在四大公开因子库中批量评测因子并看到多次检验扣减，以便我不会把"参评够多总能拿第一"的运气当能力。
- 作为一名**策略复核人**，我希望新因子提交时被强制审查公式纯度与前视偏差，以便入库因子都可复现、不可偷看未来。
- 作为一名**研究员**，我希望每份因子评测都明示是否有幸存者偏差，以便我知道股池是否按历史真实成分取数。

### M5 策略发现与策略库

- 作为一名**研究员**，我希望一条策略只有在证据齐备（足够成交笔数、足够覆盖时长、成本可行）时才能被采信，以便我不被短期小样本误导。
- 作为一名**研究员**，我希望策略证据随时间老化并自动降级、失效，以便过期规律不会被持续当真。
- 作为一名**策略复核人**，我希望策略必须经"未验证→验证中→已验证→已批准"逐级审批且作者不能批准自己的策略，以便入库策略有独立把关。
- 作为一名**研究员**，我希望只有证据充分且未失效的策略才能改编出新版本，以便派生策略不继承过期证据。
- 作为一名**投资经理**，我希望调仓时能设置容差带、遮蔽日并留存逐次调仓证据与备注，以便交易纪律可审、换手可溯。

### M6 组合优化与风险透视

- 作为一名**投资经理**，我希望优化器只使用决策时点之前的数据生成权重，以便调仓决策不含未来信息。
- 作为一名**投资经理**，我希望看到集中度、回撤、风险价值、条件期望损失等风险透视指标，以便我在收益之外看清尾部风险。
- 作为一名**研究员**，我希望期权定价在退化取值（零/负行权价、负到期天数）下明确报错，以便不会拿到看似精确实则错误的价格与希腊字母。

### M7 实盘交易安全

- 作为一名**账户主人**，我希望系统开箱默认只读、永远研究可用但不会私自下单，以便我放心安装和探索。
- 作为一名**账户主人**，我希望通过一份范围有限、定期到期的授权书来约束自主下单（品种、市场、金额、敞口、杠杆、笔数），以便风险始终在我设定的天花板内。
- 作为一名**账户主人**，我希望紧急停止一触即达、停止后只读研究仍可用，以便极端情况下我能立即掐断交易但不中断分析。
- 作为一名**账户主人**，我希望无法判定风险等级的操作一律按高风险拒绝，以便未知不会变成敞口。
- 作为一名**账户主人**，我希望每一笔真实下单都有只增不改、逐条密封的审计记录，以便事后能完整追溯"谁授权、哪份授权书、哪笔订单"。
- 作为一名**账户主人**，我希望可以选择"每笔单先经人工批准才转发"，拒绝或超时即不下单，以便人始终在回路中。
- 作为一名**账户主人**，我希望多家券商都能被统一引导接入、凭据不回显、冲突不拼凑，以便连接管理安全且反馈清晰。
- 作为一名**账户主人**，我希望系统崩溃重启后能精确恢复未完成订单而不是重复下单，对不上账时自动紧急停止并保留证据。

### M8 编队协作投研

- 作为一名**研究员**，我希望一句话就能召集一支专业编队（如投资委员会）研究一个标的，以便获得多角色、有对抗、有风控的结论。
- 作为一名**研究员**，我希望前置角色没完成时后置角色不得开工（风控失败就不出最终决策），以便最终结论建立在完整输入上。
- 作为一名**研究员**，我希望编队所有角色基于同一份基准行情和统一身份工作，以便多空双方不会各说各的价格。
- 作为一名**研究员**，我希望交白卷、只写计划、声称用模拟数据的角色被判"未达标"而非完成，以便编队报告不含水分。
- 作为一名**研究员**，我希望编队可随时取消、失败可退避重试、事后可只续跑失败部分，以便节省时间与研究用量。
- 作为一名**运维管理员**，我希望编队主题文字不能改变编队可访问的外部数据能力，未预批准的能力即使写进角色档案也被剔除，以便外部信任边界不被提示词绕过。

### M9 组合聚合与影子账户

- 作为一名**账户主人**，我希望把多家券商的只读账户聚合成一张组合视图并统一换算币种，以便一处看清总资产。
- 作为一名**账户主人**，我希望个别券商暂时离线时组合明确标注"不完整"且不把错误当成空仓，以便我不误判资产。
- 作为一名**账户主人**，我希望导入成交流水后按先进先出配对盈亏、正确识别拆股与加密币对写法，以便手工台账也能准确核算。
- 作为一名**账户主人**，我希望系统从我自己的真实盈利成交中挖掘"可复现的打法"并诚实披露有哪些币种成交被排除，以便我了解规律的适用边界。

### M10 定时研报与消息渠道

- 作为一名**渠道使用者**，我希望在我常用的聊天软件里收到定时研报、并能直接与系统对话，以便研究服务融入我的工作流。
- 作为一名**渠道使用者**，我希望陌生私聊不会被偷偷转发，必须经配对码授权，以便我的研究机器人不被陌生人滥用。
- 作为一名**研究员**，我希望定时研报必须先经我"确认"才会创建，以便聊天中的一句话不会被误当成排程指令。
- 作为一名**研究员**，我希望同一封研报绝不重复送达、系统重启后会补发没发出去的研报，以便渠道里不出现重复推送也不漏报。
- 作为一名**渠道操作员**，我希望配置渠道密钥时永不回显、保存前先做真实连通性验证、坏凭证绝不保存入档，以便渠道配置干净可用。

### M11 研究工具箱与工作台

- 作为一名**研究员**，我希望财报数据严格遵守"披露日之前不可见"，以便基本面因子不含未来信息。
- 作为一名**研究员**，我希望对存疑财务数据用本福特法则等手段验真、样本不足时明确提示不可信，以便我不被粉饰数据误导。
- 作为一名**研究员**，我希望云端文字识别必须由我显式选择才会把资料外传，以便敏感资料不会被静默外传。
- 作为一名**账户主人**，我希望上传可执行类型资料被拒绝、访问链接不得指向内网地址、远程访问必须持密钥，以便工作台不成为安全突破口。

### M12 编队流程可视化编排

- 作为一名**投资者**，我希望进入编排页就能看到全部内置团队预设及其适用场景简介，以便我不必记住预设名称，也能按本次研究诉求挑到合适的团队。
- 作为一名**投资者**，我希望选定预设后以流程图直接看到各角色分工与协作顺序，以便我快速理解这支团队将如何开展评估。
- 作为一名**投资者**，我希望发起前能临时增删角色、调整其职责说明、可用分析能力与执行时长并重新连接协作关系，以便团队配置贴合本次评估诉求，又不必长期维护模板。
- 作为一名**投资者**，我希望编排不合法（协作成环、出现孤立角色、连线断线或没有起点）时被即时高亮告知且无法发起，以便我不会提交一场无法运行的评估。
- 作为一名**投资者**，我希望填写评估标的与研究问题后一键发起，并在同一张流程图上实时看到每个角色等待、分析中、完成或失败的状态，以便我全程掌握团队的推进节奏。
- 作为一名**投资者**，我希望点击任一角色即可查看其分析过程与结论，以便我理解决策是如何逐层形成的。
- 作为一名**投资者**，我希望全部角色完成后页面默认直接展开最终决策角色的做多/做空结论与理由，以便我第一时间获得可执行答案。
- 作为一名**投资者**，我希望每次调整后的编排连同各角色结论与最终决策被完整快照留存，事后可在"我的评估历史"中按发起时同样的流程图视图回看，以便复核与追溯，且这些记录仅我本人可见。
- 作为一名**投资者**，我希望对满意的临时编排一键"另存为我的团队"，以便把顺手的角色分工沉淀为可复用的个人团队，且内置预设始终保持原样、不被我的保存改动。
- 作为一名**投资者**，我希望编排页第 1 步就有"我的自定义团队"分区，选中即可再次进入画布编排，并可原地保存更新、另存为一支新团队或删除，以便我持续打磨自己的团队配置。
- 作为一名**投资者**，我希望为每个角色勾选"使用技能"时只能在技能广场全局已通过的技能范围内选择（技能的浏览、试运行与维护统一在左侧菜单独立的"技能广场"页面进行），以便角色的研究手段组合既贴合本次诉求又质量可控，而可用分析能力的勾选边界维持不变。
- 作为一名**投资者**，我希望在"我的评估历史"按评估标的关键字（代码或名称片段）与发起时间区间筛选快照，以便在大量记录中快速定位某标的某时段的评估。
- 作为一名**投资者**，我希望点开快照中任一角色或最终决策的分析结论时，标题层级、列表与表格等被结构化渲染（如证据状态声明直接以表格呈现），表格不完整无法成表时该部分以纯文本展示，以便我高效读懂结论。

### M13 角色广场与角色准入

- 作为一名**投资者**，我希望从左侧菜单进入"智能体（角色）"页面，按内置团队预设分组浏览全部角色，并在"自建角色"分组查看我自己创建的角色，以便我系统地了解当前工程里都有哪些研究角色、各自归属哪类团队。
- 作为一名**投资者**，我希望点击任一角色进入详情页，在"角色档案"页签查看它的职责提示词、工具清单、技能清单与可用分析能力，以便我在选用前充分理解这个角色会怎么做研究。
- 作为一名**投资者**，我希望从空白创建自己的角色：自定名称、业务用途、职责提示词、可用分析能力、使用技能与执行时长，创建后它先作为仅我可见的未通过角色，以便我按个人研究方法沉淀专属角色。
- 作为一名**投资者**，我希望在角色详情的"单独运行"页签输入评估标的与研究问题，直接让该角色独立开展一次研究并看到结论，以便我不组建团队也能验证单个角色是否好用。
- 作为一名**投资者**，我希望在"评估历史"页签查看我本人对该角色的每一次单独运行记录与结论，以便复盘与持续改进。
- 作为一名**投资者**，我希望我创建的角色通过审核后对所有人生效，出现在所有人的编排可选清单中，以便好角色能被团队反复复用。
- 作为一名**投资者**，我希望我可以从已存在的角色上面派生创建的新的角色。
- 作为一名**投资者**，我希望随时编辑我创建的角色（即便已通过也不撤销其通过状态），并在不再需要时删除它，以便我持续打磨自己的角色库。
- 作为一名**运维管理员**，我希望只有在角色至少成功单独运行一次、产出合格结论后，才能在其详情页"放开通过"，审核时可查看该角色下全部人员的运行记录，以便角色准入有据可依、质量可控。
- 作为一名**运维管理员**，我希望对已通过角色随时"取消通过"，使其退出编排可选清单，以便我及时停用不再可靠的角色，同时不破坏任何历史评估快照。

### M14 技能广场与技能准入

- 作为一名**投资者**，我希望从左侧菜单进入独立的"技能广场"页面（与"智能体团队编排""智能体（角色）"并列），编排页内不再出现技能广场页签，以便我在一个专门页面集中了解系统里全部技能。

- 作为一名**投资者**，我希望点击任一技能进入详情页，在"技能档案"页签查看它的业务用途简介、方法论与操作说明全文、输入要求与输出约定，以便我在试运行与选用前充分理解这个技能做什么、需要什么、产出什么。
- 作为一名**投资者**，我希望在技能详情的"试运行"页签输入评估标的与研究问题，直接让该技能独立运行一次并看到结论，以便我不组建团队、不配置角色也能验证单个技能是否好用。

- 作为一名**投资者**，我希望从空白创建自己的技能：自定技能名称、业务用途简介、方法论与操作说明、输入要求与输出约定，创建后它先作为仅我可见的未通过自建技能，以便我沉淀个人专属的研究方法。
- 作为一名**投资者**，我希望在任一已通过技能详情页点"另存为新建技能"，其方法论、操作说明、输入要求、输出约定与业务用途自动预填、可再修改，而技能名称须重新填写且全局唯一，以便我像基于模板派生角色一样站在成熟技能肩膀上定制，并能看到派生来源留痕。
- 作为一名**投资者**，我希望通过"导入 zip 技能包"入口（预留）从系统外部导入技能，导入成功后作为仅我可见的未通过自建技能出现在本人分组，要素不完整或与金融无关的包被拒绝并说明原因，以便我把外部成熟技能引入自己的技能库。
- 作为一名**投资者**，我希望随时编辑我创建的技能（即便已通过也不撤销其通过状态、无需重新审核），并在不再需要时二次确认后删除它，以便我持续打磨自己的技能库；内置技能始终只读，我不期望被改动。

- 作为一名**投资者**，我希望我的试运行记录仅我本人可见，其他投资者互不可见，同时技能的通过状态对所有人一致，以便既能共享质量结论又互不干扰。
- 作为一名**运维管理员**，我希望只有自建技能至少成功试运行一次、产出合格结论后，才能在其详情页"放开通过"，审核时可查看该技能下全部人员的试运行记录，以便技能准入有据可依、质量可控。
- 作为一名**运维管理员**，我希望对已通过的自建技能随时"取消通过"，使其退出角色配置与编排可选清单，以便我及时停用不再可靠的技能，同时不破坏任何历史评估快照与试运行记录。
- 作为一名**运维管理员**，我希望技能广场页面保留仅管理员可见的导入专区：手动导入第三方金融技能包或一键自动同步金融相关技能；管理员装配的全局技能沿用"任一次试运行成功即全局通过"，新装配技能一律未通过，更新版本保留原通过状态，与金融无关或要素不完整的包应被拒绝。

## 3. Acceptance Test Cases（验收用例）

> 采用标准 Gherkin 语法。每个场景对应一个独立可验收业务点；"假定/当/那么"分别对应 Given/When/Then。

### 3.1 市场识别与行情服务（M2）

```gherkin
功能：按代码识别市场与跨供应方取数

  场景：带标准后缀的代码被正确归类到对应市场
    假定 研究员提供代码 "600519.SH"
    当 系统识别其所属市场
    那么 该代码被识别为中国 A 股（上海）

  场景：识别大小写不敏感
    假定 研究员提供代码 "000001.sz"
    当 系统识别其所属市场
    那么 该代码与 "000001.SZ" 等同，识别为中国 A 股（深圳）

  场景：不带后缀的 1 至 5 位字母代码兜底识别为美股
    假定 研究员提供代码 "AAPL"
    当 系统识别其所属市场
    那么 该代码被识别为美股，且该兜底规则优先级低于所有其他已知形态

  场景：实在无法识别的代码默认按 A 股处理
    假定 研究员提供代码 "random-string"
    当 系统识别其所属市场
    那么 该代码按中国 A 股尝试服务，而不是报错丢弃

  场景：主连合约代码被识别为中国期货
    假定 研究员提供代码 "RB0"
    当 系统识别其所属市场
    那么 该代码被识别为中国期货主连合约
    但是 不在主连白名单内的 "TSLA0" 不得被误判为期货

  场景：裸六字金属外汇与加密稳定币报价被严格区分
    假定 研究员分别提供 "XAUUSD" 与 "BTCUSDT"
    当 系统识别二者所属市场
    那么 前者归为外汇（贵金属），后者归为加密货币

  场景：自动模式按市场专属顺序逐家尝试、取齐即停
    假定 研究员一次请求同一市场的 5 只标的
    当 第一家行情供应方成功提供全部 5 只标的的数据
    那么 系统不再打扰后续供应方

  场景：部分成功时仅带缺失标的继续下一家
    假定 第一家供应方只返回 5 只标的中的 4 只
    当 系统继续按顺序尝试
    那么 仅对那 1 只缺失标的继续尝试，已取得的 4 只不重复取数
    而且 每只标的分别记录实际供数方

  场景：单只标的在一条替补顺序上最多尝试 5 家
    假定 某市场替补顺序上有 8 家供应方
    当 前 5 家均未提供某只标的的数据
    那么 系统停止继续尝试并将该标的列入"未解决"清单

  场景：港股标的不得被串到美股供应顺序上浪费尝试次数
    假定 研究员请求一只港股标的
    当 系统安排取数
    那么 必须按港股专属顺序尝试，不得因某家也服务港股而改走美股顺序

  场景：加拿大主板与创业板代码互为迁板别名
    假定 研究员提供 ".TO" 代码而该代码在多伦多主板查无记录
    当 系统尝试取数
    那么 自动改用对应 ".V" 创业板代码尝试，结果仍挂在研究员点名的代码下并留痕
    而且 两个代码同时点名且仅有一边有数据时，只取一次、两边复用同一份记录

  场景：显式点名自有行情库时绝不联网补数
    假定 研究员以 "local:" 前缀请求一只本地库中不存在的标的
    当 系统取数
    那么 直接明示"本地库缺该标的"，绝不上网补数

  场景：同一只标的同时带前缀与不带前缀视为重复请求
    假定 同一请求中同时出现 "local:600519.SH" 与 "600519.SH"
    当 系统受理请求
    那么 该请求因重复而被拒绝

  场景：显式点名的特定供应方失败后不得换源糊弄
    假定 研究员显式指定由 FMP 供数，而该服务稳定取数入口已停用
    当 系统取数失败
    那么 直接明示失败并说明配置问题，不得返回别家数据顶替

  场景：伊朗托曼报价渠道不得被替换为美元稳定币渠道
    假定 研究员显式点名伊朗本地加密渠道
    当 该渠道取数失败
    那么 直接失败，不得改用以美元稳定币报价的渠道（价格尺度相差约六个数量级）

  场景：用户重排供应方顺序必须是该市场名单的完整排列
    假定 用户为 A 股只填写了名单中的两家供应方作为新顺序
    当 系统读取该设置
    那么 设置无效并告警，继续使用默认顺序
    但是 清空该设置即恢复默认顺序

  场景：小写 m 表示分钟、大写 M 表示月，严格区分
    假定 研究员分别请求周期 "1m"、"30M"、"1M"
    当 系统归一化周期
    那么 分别识别为 1 分钟、30 分钟、1 个月

  场景：不存在的周期与乱写周期被拒绝
    假定 研究员请求周期 "2W" 或 "BANANA"
    当 系统校验周期
    那么 请求被拒绝，并回列所有可选周期

  场景：供应方不支持的周期必须明示，严禁拿日线冒充
    假定 研究员向不支持分钟线的 A 股供应方请求 1 分钟数据
    当 系统处理请求
    那么 直接返回"没有"且不发起无效请求，不得用日线数据顶替

  场景：起止日期倒置或紧凑写法被拒绝
    假定 研究员给出起始日 2026-08-21、截止日 2026-08-01
    当 系统校验日期区间
    那么 请求被拒绝并写明两个日期；"20260101" 这类紧凑写法同样被拒绝

  场景：技术指标周期取值为零或负数被丢弃
    假定 研究员请求均线，窗口取值为 0 和 -3，另有一个为 5
    当 系统生成指标
    那么 仅生成窗口为 5 的均线，非法取值被丢弃

  场景：周线月线一律由日线在边界聚合
    假定 研究员请求某标的周线数据
    当 任意取数方式处理该请求
    那么 实际向供应方请求日线，再按周一至周日聚合，时间戳钉在该周最后一个交易日
    而且 开盘取首日、收盘取末日、最高价取最高、最低价取最低、成交量求和

  场景：自有库数据只能由细聚粗、不能由粗造细
    假定 本地库仅有日线记录，研究员请求 4 小时线
    当 系统处理请求
    那么 原样返回日线并告警"无法升采样"，不得编造 4 小时数据

  场景：每只标的默认最多返回 250 条，超出时等距抽样并钉住最后一条
    假定 某标的请求区间含 365 条日线
    当 系统返回结果
    那么 返回等距抽样后的记录、最后一条必在样本中、日期严格递增，并附原始与返回条数说明
    但是 刚好 250 条不触发抽样；上限设为 0 表示不限；负数视为非法并按默认上限执行

  场景：未取到的标的进入"未解决"清单，全部成功时不出现该清单
    假定 一批标的中有一只已退市
    当 取数结束
    那么 该标的出现在"未解决"清单；其余成功标的正常返回
    而且 全部成功时答复中完全不出现"未解决"清单

  场景：K 线结构非法行被清洗
    假定 某条记录最高价低于最低价，或最高最低包不住开盘收盘
    当 数据进入集中入口
    那么 该非法行默认被剔除（也可配置为报错或告警保留）
    但是 四价相等且零成交量的平盘十字星视为合法

  场景：零价永远剔除，负价市场可经专门开关放行
    假定 数据中出现价格为 0 的记录
    当 系统清洗数据
    那么 该记录一律剔除；开启负价市场开关后负价可保留，但零价仍永远剔除

  场景：成交量单位无实测证据时留空，绝不猜测
    假定 某新兴市场的成交量单位未经实测确认
    当 系统输出数据留痕
    那么 成交量单位字段留空（未知），不得自行填"股"或"手"

  场景：A 股成交量跨供应方统一按"手"计量
    假定 某供应方原生按"股"提供 A 股成交量
    当 数据在出口处统一口径
    那么 换算为"手"（1 手 = 100 股）后输出

  场景：组合内混用两种复权口径必须告警
    假定 同一组合中一只标的采用加减式分红复权、另一只采用乘法复权
    当 系统核对口径
    那么 输出告警，提示跨证券比较存在偏差
    但是 两只标的同为加减式分红复权不算混用

  场景：供应方"查询被拒"与"查无数据"必须分清
    假定 某数据中心对退役报表返回"被拒绝"应答
    当 系统解读应答
    那么 明示报错（被拒绝），不得当成零笔数据；只有真正的空结果才算零笔

  场景：分页取数不得静默截断
    假定 某供应方每页最多 500 根、最多翻 12 页
    当 请求区间超过该上限
    那么 系统反向翻页、重叠去重、不丢结束日当天记录；翻满页数仍未取完时报错，不得拿残缺历史充当短历史
```

### 3.2 智能投研对话与身份消歧（M1）

```gherkin
功能：研究主流程、身份消歧与结论核据

  场景：取数前必须先锁定身份，查名与取数不得抢跑
    假定 研究员提问涉及一只尚待确认身份的标的
    当 系统开始研究
    那么 必须先完成查名并锁定身份，未锁定身份的取数请求被拒绝

  场景：研究员明示只分析 A 股时锁定 A 股、禁用同名港股
    假定 研究员说"只分析 A 股恒瑞医药"
    当 系统做身份判定
    那么 锁定 A 股代码并把港股代码列入禁用，约束来源记为"研究员显式给出市场"

  场景：研究员要求比较 A/H 两地时两个候选都不锁定
    假定 研究员说"比较恒瑞医药 A 股和港股"
    当 系统做身份判定
    那么 保持歧义、两个候选都不锁定，供比较使用

  场景：否定句不构成市场授权
    假定 研究员只说"分析恒瑞医药，不要看港股"但未正面指定市场
    当 系统做身份判定
    那么 不得据"不要看港股"反推为 A 股授权，宁可不锁定

  场景：只说公司名不给市场且存在 A/H 歧义时宁可少锁
    假定 研究员只说"分析恒瑞医药"
    当 系统做身份判定
    那么 不锁定任何一个身份，进入澄清或继续查名流程

  场景：上一轮锁定的身份不得借给本轮新标的
    假定 上一轮已锁定某 A 股身份，本轮研究员提到另一只裸代码
    当 系统做身份判定
    那么 不得跨问题借用身份，新标的须独立查名

  场景：身份自动恢复的尝试次数有上限
    假定 身份未锁定或缺价格，系统自动补做查名或取数
    当 查名与取价尝试合计达到 5 次或恢复达到 6 轮
    那么 停止自动恢复，仅当真歧义、真冲突或预算耗尽时才请研究员澄清
    而且 自动恢复期间不得要求研究员确认"是否继续"

  场景：结论数字必须四要素齐备且与实际取数对得上
    假定 研究结论中出现一个价格数字
    当 系统发布前核据
    那么 该数字必须能在本次取数中找到，并同时具备规范代码、数据来源、币种、截至日期
    而且 取值区间之外的数字判冲突

  场景：推导数字必须算式正确且锚定真实观察值
    假定 结论给出"建议买入价 = 收盘价 × 0.97"
    当 系统核据
    那么 收盘价必须为真实观察值、算式必须正确、涨跌幅方向必须与公式一致

  场景：舍入容差按所写最后一位的半个单位判定
    假定 结论写"约 5%"，真实值为 5.4955%
    当 系统核据
    那么 判定为可接受；若真实值为约 6% 则判冲突

  场景：百分比按百分点比较
    假定 结论中出现 0.5 个百分点的变化
    当 系统核据
    那么 按 0.5 个百分点判定，不得误读为 50 个百分点

  场景：停牌日不得冒充"最新收盘价"日期
    假定 某标的最近一个交易日停牌无有效收盘价
    当 结论引用"最新收盘价"
    那么 日期取最后一个有有效收盘价的交易日；收盘价全缺的标的整只不进依据表，缺失值显示"—"

  场景：无据数字修订最多两版，第二版剪裁发布
    假定 第 1 版结论含无据数字被退回，第 2 版仍含无据数字
    当 系统发布结论
    那么 保留全部合格分析，剪掉无据数字并逐处标注"已剪裁（降级）"，一次性剪尽正文与表格
    但是 完全无价格证据或身份未锁定时不得剪裁发布，只能出具安全门槛拒绝

  场景：研究员用什么语言提问就用什么语言作答，且中英结论一致
    假定 研究员用中文提问
    当 系统发布结论
    那么 使用中文作答；同一数字主张在中文与英文下结论必须一致，无据度量两种语言都拒绝

  场景：同一取数反复失败第 8 轮终止
    假定 研究中同一取数动作持续失败、没有新信息
    当 无进展守护计数到第 8 轮
    那么 研究以"无进展"为由终止并给出可读原因

  场景：换措辞重复读取同一结果第 9 轮终止
    假定 研究助手反复用不同措辞读取同一份结果而无新信息
    当 计数到第 9 轮
    那么 研究终止

  场景：连续 30 分钟既无回答也无取数结果则停滞失败
    假定 一场研究连续 30 分钟没有任何进展
    当 停滞看门狗触发
    那么 研究判失败、留档并终止；中途恢复则警告清零；设为 0 可关闭该守护

  场景：流式回答中断恰好重试一次，连续两次失败即整单失败
    假定 研究模型的流式回答中断
    当 系统重试
    那么 重试 1 次；连续 2 次失败则整单失败；供应方明确拒绝的请求立即失败不重试
    而且 等待按 1→2→4 秒翻倍、封顶 30 秒，供应方明示等待秒数时遵从但不超封顶

  场景：内容被审核拦截时跳过该轮，连续 10 次熔断
    假定 单轮研究内容被供应方审核拦截
    当 系统处理
    那么 跳过该轮继续研究；连续 10 次被拦截则提前失败
    而且 整场拦截占比达到或超过 5% 时结果中给出警告并写入研究卡片

  场景：只读研究工具超时返回诊断，写操作超时不得提前报失败
    假定 某只读工具运行超过 1800 秒
    当 超时发生
    那么 返回"工具超时"诊断；而下单等有副作用的操作超时只发警告，必须等待真实结果

  场景：确定性问题重复提问直接引用已有结论
    假定 研究员以相同条件（顺序归一化后）再次调用声明"答案不变"的纯研究工具
    当 系统受理
    那么 同一问题只真正取数一次，第二次直接引用；但失败结果绝不被当成成功结论引用

  场景：篇幅达到阈值时自动压缩且不重复真实下单
    假定 一场研究的篇幅达到 40000 个计量单位
    当 系统压缩
    那么 50% 时先微压缩、70% 时对话折叠；折叠保留最近 3 条取数结果与最近 6 个回合
    而且 下单等写操作的副作用绝不因压缩而重复执行

  场景：同一时刻同一会话只允许一个研究在跑
    假定 一个会话已有研究正在进行
    当 研究员再次提问
    那么 第二个请求被拒绝（会话忙碌）

  场景：已结束历史默认不重放，可全量或按编号增量续播
    假定 研究员重新打开一场已结束的会话
    当 系统恢复会话内容
    那么 默认不重放已结束历史；研究员可选择全量续播或按编号增量续播

  场景：系统重启后未完成回答只恢复一次并明确标注
    假定 流式回答在最近一次进度留存之后因系统重启中断
    当 系统恢复
    那么 未完成回答最多恢复一次，并标注"已中断／部分内容／因系统重启恢复"，重复对账不重复恢复

  场景：研究目标自动续作最多 3 次
    假定 一轮研究结束但目标验收标准尚未覆盖
    当 系统自动续作
    那么 注入验收标准与近期证据快照续作，同一目标最多自动续作 3 次；即使看似达标也须做一次终态审计

  场景：含"立即实盘下单"诉求的目标内容直接拒绝
    假定 研究员试图设立内容为"立即实盘下单"的研究目标
    当 系统受理目标
    那么 该目标被拒绝；目标只能承载研究类诉求

  场景：假设状态只能沿探索中→验证中→已验证推进
    假定 研究员登记一条研究假设
    当 管理假设状态
    那么 只允许"探索中→验证中→已验证（可附失效备注）"，不得登记实盘交易类状态
```

### 3.3 历史回放、因子与策略（M3/M4/M5/M6）

```gherkin
功能：多市场历史回放与业绩核算

  场景：A 股回放遵守 T+1、禁做空、整手与税费规则
    假定 一个 A 股策略在回放中当日买入
    当 回放核算成交
    那么 当日买入不得当日卖出、不足 100 股向下取整、按最低 5 元佣金与卖出方 0.05% 印花税核算

  场景：涨停禁买、跌停禁卖，且以当根开盘实际成交价判定
    假定 标的开盘记账价（含滑点后）达到涨停
    当 策略发出买入信号
    那么 买单不成交；判定一律用当根开盘实际记账价对比昨收，不得用当根收盘价偷看未来

  场景：无基准价时放行而非虚构涨跌停边界
    假定 某根K线缺少昨收基准价
    当 回放判定涨跌停
    那么 该笔交易放行，不得虚构一个基准价来拦截

  场景：停牌行情最多沿用前价 5 根
    假定 标的连续停牌
    当 回放读取行情
    那么 最多沿用前价 5 根，之后留空；长期停牌按最后收盘价估值；整段空缺的标的剔除并告警

  场景：热身 K 线只供指标计算不计业绩
    假定 回放配置了热身根数
    当 热身区间内出现交易信号
    那么 热身期不计入业绩；同时给热身根数又给评估起始日则报错；热身结束后无剩余 K 线也报错

  场景：信号当根产生、次根开盘成交
    假定 策略在某根 K 线上产生交易信号
    当 回放撮合
    那么 在下一根 K 线开盘成交；期权同样次根成交，到期当根按内在价值结算、价外归零

  场景：回放结束强制平仓并计入全部成本
    假定 回放到期仍有持仓
    当 回放结束
    那么 强制平仓、出场原因记"回放结束"，出场费、滑点、乘数全部计入最终净值

  场景：混合结算币种组合在取数前被拒并逐一点名
    假定 一个资金池同时包含人民币、美元、印度卢比标的
    当 启动回放
    那么 取数之前直接拒绝并逐一点名涉事币种；同币种跨市场允许组合，混合净值曲线视为非法

  场景：停牌跨缺口的真实涨跌幅必须保留
    假定 某标的停牌前 110 元、复牌后 121 元
    当 计算收益率
    那么 必须记 +10%；若用陈旧价填充会压低波动率、虚增夏普，该做法被禁止

  场景：权益为零时各项指标保持有限不得炸锅
    假定 回放权益曲线触及 0
    当 计算夏普、回撤、年化等指标
    那么 由此产生的无穷大被清除，所有指标保持有限值或留空

  场景：换手率按实际成交（整手取整后）计算
    假定 目标权重未变但因价格漂移发生多次纠偏成交
    当 统计换手
    那么 按实际成交统计换手并如实反映纠偏；被拒目标记零换手

功能：因子审查与严格评审

  场景：因子公式只能做数值计算、不得查阅外部资料或联网
    假定 研究员提交一个含查阅外部资料行为的因子公式
    当 纯度门审查
    那么 该因子被拒绝；动态生成并执行内容、操作系统、绕过限制、私自引入外部内容同样一律拒绝
    而且 公式文本开头只允许注释、引用说明、纯数值计算步骤、因子编号常量与明文字典

  场景：因子不得使用探针日之后的数据
    假定 把探针日之后的数据篡改为空缺或天文数字
    当 重算因子在探针日的取值
    那么 探针日的值必须在极小容差内不变、空缺位置一致；否则判前视偏差、因子被拒
    但是 空缺率超 95% 的面板可判数据不足而跳过

  场景：因子评测必须使用前复权价格
    假定 某创业板个股除权日原始跌幅显示 -41.82%、真实涨幅为 +5.40%
    当 因子评测取价
    那么 必须使用前复权价，除权日收益为 0、最新 K 线仍是真实成交价

  场景：幸存者偏差必须明示并透传到报告
    假定 股池取自指数历史权重（含已离开成分的标的）
    当 产出评测结果
    那么 标注"无幸存者偏差、成分按当时为准"及来源日期；若取数失败降级为手工名单，必须标注"有幸存者偏差、已降级"

  场景：要求行业中性化的因子缺行业标签即拒算
    假定 标普 500 面板缺少行业标签列
    当 评测 19 个要求行业中性化的因子
    那么 拒算；标签表与价格表必须行列严格对齐

  场景：严格评审四档结论
    假定 一个因子全样本显著（达到显著性倍数门槛、样本数足够）且样本外不倒
    当 严格评审出结论
    那么 判"确认存活"
    但是 训练显著、样本外落入噪声带判"仅训练有效"；样本外符号翻转判"反转"；样本不足等其余情形判"噪声"

  场景：成本必须侵蚀高换手因子，参与率超量只部分成交
    假定 某因子换手率极高
    当 计入交易成本后评测
    那么 高换手因子被成本侵蚀的程度必须显著大于低换手因子；成交额参与率设上限，超量部分不补单且缺口如实报告
    而且 未知、零、负成交量视为不可交易，参与率必须在 (0,1] 区间

功能：策略发现证据流水线

  场景：取证五道硬门任一不过则整次运行零证据入库
    假定 一次回放运行的净值曲线中间存在空缺值
    当 证据门核验
    那么 整次运行被拒（运行成功、指标台账齐全可读、成交笔数大于零、净值存在且连续，五者缺一不可）

  场景：少于 10 笔成交无论覆盖多久证据都判不足
    假定 一条策略回放仅有 6 笔成交但覆盖了 3 年
    当 证据质量评级
    那么 评级为"不足"；成交笔数达标但覆盖不足 730 天判"勉强"；两者都达标才可判"充分"
    而且 盈亏平衡手续费低于 5 个基点时标"成本敏感"

  场景：证据记录一旦生成不可修改，重建采用整体替换
    假定 证据重建过程中系统崩溃
    当 重新查看证据
    那么 旧证据保持完好；新证据必须全部算完后一次性替换

  场景：策略生命状态按衰减信号逐级降级
    假定 一条"在用"策略连续 3 次出现警告信号
    当 状态机推进
    那么 转为"监控中"；监控中连续 2 次衰减转"已衰减"；已衰减连续 3 次危险转"停用"
    但是 一次健康信号即可从监控回到在用；数据不足必须明确判"数据不足"，不得冒充健康

  场景：审批不得跳级、作者不得批准自己的策略
    假定 策略作者试图直接把策略置为"已批准"
    当 四眼治理检查
    那么 必须逐级走"未验证→验证中→已验证→已批准"；作者与批准人为同一人时给出四眼提示
    而且 登记治理信息时"预期用途"和"局限性"缺一不可

  场景：证据老化按区间月末锚定判定
    假定 某策略证据区间距今恰好 180 天
    当 读取策略时判定新鲜度
    那么 恰好 180 天判"失效"、恰好 90 天判"老化"；区间无法解析时一律按失效处理（宁可不采信）

  场景：只有证据充分且未失效的父策略允许改编
    假定 一条父策略证据已失效，研究员请求改编新版本
    当 系统受理改编
    那么 拒绝写入；因子不可改编；改编必须更换市场或更换名称，同名同市场视为无意义改编
    而且 子策略以"登记"状态重走完整验证，旧审批字段清空但保留出处链接

  场景：再平衡容差带内不折腾，真实目标改变任何带宽都执行
    假定 设置 5% 漂移带后权重仅漂移 2%
    当 触发再平衡检查
    那么 不调仓；但真实目标发生改变时无论带宽大小都执行
    而且 负、空、无穷带宽拒绝；默认带宽为零

  场景：遮蔽日内即使目标变零也不卖出
    假定 某日被设为遮蔽日且当日目标权重变为零
    当 再平衡执行
    那么 当日不调仓；遮蔽安排与"持有不调"模式互斥；遮蔽日期与交易日无交集时报错

  场景：优化器观察窗口不含决策当根
    假定 改动决策日当天的收益
    当 重新生成决策日权重
    那么 权重不变（三类优化器共同遵守因果性）

  场景：优化器无解或求解失败必须明示，不得静默退回等权
    假定 一组约束下优化器求不出可行权重或求解过程失败
    当 系统产出调仓方案
    那么 直接报错说明原因，不得悄悄退回等权方案冒充成功

  场景：自动研究产出策略建议前必须先有回放验证证据
```

```gherkin
    那么 画布提示"流程缺少起点角色"，"发起评估"置灰

  场景：全部问题消除后解除拦截
    假定 画布曾因循环依赖而阻断发起
    当 投资者改正连线使流程合法
    那么 高亮与文字提示消失，"发起评估"恢复可用，并提示"流程合法，可以发起"

  场景：内置预设本身不被临时调整改动
    假定 投资者基于投资委员会预设完成了一轮调整与评估
    当 投资者返回预设列表再次选择投资委员会
    那么 画布载入的仍是该预设的原始版本，上一轮的临时调整不被带入

功能：一键发起评估与流程图状态联动

  场景：发起前必须填写评估标的与研究问题
    假定 协作流程已合法但评估标的或研究问题为空
    当 投资者点击"发起评估"
    那么 发起被拦截并提示必填项，评估不开始

  场景：示例评估按投资委员会协作顺序推进
    假定 投资者选择投资委员会预设，标的填 "600519.SH"，问题填"当前市场环境下做多还是做空"
    当 评估发起
    那么 多头研究员与空头研究员同时进入分析中；二者均完成后首席风险官开工；风控完成后投资经理终裁
    而且 投资经理最终给出做多或做空的方向及理由

  场景：节点状态四态实时呈现
    假定 一场团队评估正在进行
    当 各角色陆续推进
    那么 每个节点在流程图上实时呈现"等待中/分析中/已完成/失败"之一，同一协作层的节点同时亮起

  场景：上游未成功下游不得开工

    当 其下游角色到达计划开工时点
    那么 下游节点保持等待并以"受阻"注明被哪个角色卡住，不得在缺少上游输入下产出结论

  场景：点击节点查看该角色分析过程与结论
    假定 投资者在评估进行中点击任意角色节点
    当 详情侧栏展开
    那么 已完成角色展示分析过程摘要与正式结论，未完成角色仅展示当前进展与职责说明

  场景：角色内部分析步骤由角色自主展开
    假定 某角色已进入分析
    当 该角色开展研究
    那么 在其职责说明与勾选的可用分析能力范围内，具体先做什么、后做什么由该角色自主决定
    但是 角色与角色之间的协作顺序固定不变

  场景：全部完成后默认展开最终决策
    假定 末层最终决策角色完成终裁
    当 流程图进入全部完成状态
    那么 页面默认展开该角色的结论，明示做多/做空方向与理由，并支持回溯查看各上游角色的结论

  场景：评估进行中可随时取消
    假定 一场评估正在进行
    当 投资者点击"取消评估"
    那么 未开工角色不再开工、正在分析的角色停止工作，整场评估以"已取消"终态留存
    而且 取消的其余处理纪律沿用编队既有规则

功能：评估快照与我的评估历史

  场景：临时调整默认不自动另存、随评估快照留存
    假定 投资者在预设基础上调整了角色、连线与角色技能并完成一次评估，期间未点击"另存为我的团队"
    当 评估结束
    那么 系统不自动生成可复用的个人团队方案，但调整后的完整流程图（含各角色使用技能）随本次评估记录以快照形式留存

  场景：历史回看与实时视图一致
    假定 投资者在"我的评估历史"中打开一条已完成评估
    当 页面打开该记录
    那么 以发起时同样的流程图视图展示当时的协作流程、各角色结论与最终决策，节点状态定格为终态

  场景：评估记录仅本人可见且长期留存
    假定 投资者甲完成一次团队评估
    当 投资者乙查看自己的评估历史
    那么 乙看不到甲的任何评估记录
    而且 甲本人的评估记录长期保留、不自动清理

  场景：历史列表可识别评估要素与终态
    假定 投资者打开"我的评估历史"
    当 列表呈现
    那么 每条记录至少展示发起时间、所用团队预设、评估标的、研究问题、终态（成功/失败/已取消）与最终结论摘要

  场景：按评估标的关键字模糊筛选历史

    当 投资者在筛选框输入 "600519" 或 "茅台"
    那么 列表仅保留标的代码或名称匹配该片段的本人记录，不相关记录不展示

  场景：按发起时间区间筛选历史
    假定 投资者选定发起时间的起止日期
    当 筛选生效
    那么 列表仅保留发起时间落在该区间（含起止当日）内的本人记录

  场景：标的与时间两个筛选条件可组合、可清空
    假定 投资者同时给出标的关键字与发起时间区间
    当 筛选生效
    那么 列表仅保留同时满足两个条件的记录
    而且 清空全部筛选条件后恢复展示全部本人记录

功能：角色"使用技能"目录

  场景：角色技能默认展示本团队预设并集
    假定 投资者在画布载入投资委员会并选中某角色
    当 查看该角色的"使用技能"
    那么 默认列出该团队预设中各角色已配置技能的并集目录并呈现该角色的原勾选
    而且 "可用分析能力"的勾选目录与边界维持原样，不受技能设置影响

  场景：经"新增"从全量已通过技能中自由勾选
    假定 投资者正在编辑某角色的"使用技能"
    当 点击"新增"
    那么 展示系统全部"已通过"技能的清单及其业务用途简介，可自由勾选追加到该角色
    但是 未通过的技能不出现在该清单中、不可被勾选

  场景：角色技能配置随评估快照定格
    假定 投资者为某角色追加勾选了技能并完成评估
    当 事后打开该评估快照
    那么 该角色当时勾选的技能与职责、能力、执行时长、连线一并定格展示

功能：另存为我的自定义团队

  场景：流程合法时可另存为我的团队
    假定 画布上的编排已通过全部实时校验
    当 投资者点击"另存为我的团队"，填写团队名称（适用场景简介留空）并确认
    那么 系统保存一支仅本人可见的自定义团队，内容为当前画布全部角色、连线、职责说明、可用分析能力、使用技能与执行时长

  场景：团队名称必填且与本人已有团队重名时拦截
    假定 投资者已有名为"我的增强版投委会"的自定义团队
    当 投资者再次以同名另存
    那么 保存被拦截并提示更换名称，原团队不被覆盖；仅简介不同不能绕过重名拦截

  场景：另存不改动内置预设、自定义团队之间也互不影响
    假定 投资者基于投资委员会调整后另存为自定义团队
    当 投资者再次选择内置投资委员会，或打开另一支自定义团队
    那么 内置投资委员会载入的仍是原始版本，另一支团队也不包含本次调整

  场景：第 1 步分区展示我的自定义团队
    假定 投资者已保存两支自定义团队
    当 进入编排页第 1 步
    那么 "内置团队预设"与"我的自定义团队"两个分区同时呈现，自定义团队卡片展示名称、适用场景简介与角色数量
    而且 投资者尚无自定义团队时，该分区以空状态提示并说明如何从编排中另存

  场景：自定义团队可再次载入编排并原地更新
    假定 投资者从"我的自定义团队"选中一支团队进入画布并完成修改
    当 点击"保存"
    那么 该团队定义被原地更新（名称与简介亦可修改），再次选择时载入的即为更新后版本

  场景：自定义团队可另存为一支新团队
    假定 投资者在一支已有自定义团队的画布上继续调整
    当 点击"另存为我的团队"并以新名称保存
    那么 生成另一支独立团队，原团队保持修改前内容不变

  场景：删除自定义团队须二次确认且不影响历史快照
    假定 投资者要删除一支自定义团队
    当 点击删除并在二次确认中确认
    那么 该团队从本人分区移除
    而且 此前使用该团队发起的评估快照仍可完整回看，其流程图与结论不因删除而缺失

  场景：自定义团队仅本人可见可用可管理
    假定 投资者甲保存了自定义团队
    当 投资者乙进入自己的编排页
    那么 乙看不到、也无法使用或管理甲的自定义团队

  场景：载入引用了已退出清单技能的自定义团队时拦截发起
    假定 某自定义团队保存后，其角色引用的一项技能已从可选清单退出
    当 投资者载入该团队并尝试发起评估
    那么 画布对该失效引用高亮提示，投资者移除或替换该项之前不得发起

功能：角色与最终决策结论的结构化展示

  场景：角色结论按业务文档结构渲染
    假定 某角色快照结论含标题层级、编号/项目列表、一张"证据状态声明"表格与加粗等重点标注
    当 投资者在快照详情中点击该角色
    那么 标题、段落、列表、表格（含表头与行列）及重点标注均按结构渲染，证据状态以可读表格呈现

  场景：残缺不成表的内容降级为纯文本
    假定 某角色结论中一段表格行列不齐、无法构成完整表格
    当 结构化呈现
    那么 该段以纯文本原样展示，不丢失文字
    而且 同篇结论中的其他表格与结构化内容仍正常渲染

  场景：最终决策结论默认展开时同样结构化呈现
    假定 投资者打开一份全部完成的评估快照
    当 最终决策结论默认展开
    那么 最终决策正文与各角色结论适用相同的结构化呈现口径，不退回整段纯文本
```

```gherkin
功能：角色页展示与角色创建

    当 投资者乙浏览角色页

功能：角色详情页与单独运行

  场景：详情页分三个页签
    假定 投资者打开任一角色详情页
    当 页面呈现
    那么 页面提供"角色档案""单独运行""评估历史"三个页签

  场景：角色档案展示提示词、工具与技能
    假定 投资者在"角色档案"页签
    当 查看档案内容
    那么 页面展示业务用途、职责提示词全文、工具清单、技能清单与可用分析能力
    而且 每项工具与技能附业务用途说明

  场景：以标的与研究问题单独运行角色
    假定 投资者在某角色详情页打开"单独运行"页签

    假定 一次单独运行返回空稿、只列计划或声称使用模拟数据
    当 运行成果验收

    而且 产出实质结论、有据可查的运行判为成功

    假定 投资者在"评估历史"中打开一条成功运行记录
    当 记录详情展开
    那么 该次结论按标题、段落、列表、表格等结构化呈现，残缺不成表部分降级为纯文本

    假定 某角色已有多名投资者发起单独运行

    那么 管理员可查看该角色下全部人员的运行记录与结论，不受"历史仅本人可见"限制

    假定 某角色已有至少一次合格的单独运行记录
```

### 4.5 策略证据与生命周期规则

**策略发现六阶段**：登记假设 → 历史回放取证 → 样本外留出验证 → 影子盘对照 → 小仓实盘金丝雀 → 退役；任何策略建议对外产出前，必须先有回放验证证据（滚动窗口数、盈利窗口占比、结论一致性）。

**证据质量评级**
- 不足：成交 < 10 笔（无论覆盖多久）。
- 勉强：笔数达标但覆盖 < 730 天；覆盖天数按多段区间并集跨度计。
- 充分：≥ 10 笔且 ≥ 730 天（踩线算合格）。
- 成本敏感：盈亏平衡手续费 < 5 个基点即告警。
- 取证缓冲：笔数 +5、费用 +10 基点、覆盖 +365 天。

**生命周期状态与转换**
- 策略台账：登记 → 评测中 → 在用 → 监控中 → 已衰减 → 停用。
- 降级走向：在用连续 3 次警告 → 监控；监控连续 2 次衰减 → 已衰减；已衰减连续 3 次危险 → 停用；一次健康即可由监控回到在用；数据不足不得冒充健康。
- 审批流：未验证 → 验证中 → 已验证 → 已批准（不得出生即批准、不得跳级；作者≠批准人，四眼检查目前仅提示）。
- 新鲜度：证据区间月末距今 90 天=老化（转观察），180 天=失效（转停用）；区间不可解析按失效。
- 改编：仅"证据充分且未失效"的父策略可派生；因子不可改编；必须换市场或换名；子策略回到"登记"重走全流程。

**因子评测纪律**
- 显著性门槛默认 2.0 倍标准差；全库批量扫描时提高到 3.5 倍；每只因子最少 30 个有效样本。
- 批量评测必须报告多次检验扣减；基本面数据列须以专门前缀与行情列区分；借券费用只向空头收取。

**组合优化规则**
- 三类优化器：均值方差、风险平价、换手感知；观察窗口一律不含决策当根。
- 无解或求解失败时直接报错，不得静默退回等权方案。

**再平衡规则**
- 证据：笔数、根数、实际换手均从不可改的成交记录统计；价格漂移导致的纠偏也要计入。
- 容差：带内不折腾；真实目标改变无视带宽；默认带宽为零；负/空/无穷带宽拒绝。
- 遮蔽：仅指定日期或"每月首个交易日"可调仓；遮蔽日目标变零也不卖；与持有模式互斥。
- 备注：逐次记录换手、进出标的、最大变动并出台账与文字说明；同向改仓被丢弃须留痕告警，自然漂移不算丢弃。

### 4.6 实盘安全核心规则

1. **默认只读**：开箱无下单能力；只读名单不含以一概全的写法；券商配置中以一概全的写法一律拒绝（含挂别名、仿冒名称识别）。
2. **授权书不可由助手创建或放宽**：只经"提案 2–4 档（全部钳制天花板）→ 严格真值批准 → 凭证最后写入"流程；提案一次性消费；只能收窄、放宽须重签；默认 30 天到期；结构性违规（黑名单/品种/市场）直接拒绝，数量性违规（金额/敞口/杠杆/笔数/资金）暂停请重新授权。
3. **下单门禁固定顺序**：授权书存在 → 未过期 → 未紧急停止 → 账户绑定匹配 → 要素可解析 → 只读核对持仓资金（读失败即拒）→ 黑名单 → 品种白名单 → 市场大类 → 单笔金额 → 成交后总敞口（多空总值不抵消）→ 杠杆 → 当日笔数（世界标准时间日切）→ 资金兜底（仅买入）→ 市值/流动性下限（无数据即拒）。
4. **金额防绕过**：显式金额与"数量×价格"取较大值；限价买入按市价与限价孰高；垃圾限价拒单。
5. **故障关闭**：未知风险按写工具处理；人工核定清单压过工具自行标注；能力登记时即剔除下单能力、每次调用再过门禁。
6. **紧急停止**：标记存在即生效（全局或按券商，全局优先）；下单在任何对外动作之前直接拒绝；只读研究不停；默认只撤挂单，平仓须逐份显式勾选，平仓先撤后平、读失败不平。
7. **交易完整性**：先留存待处理标记（必须保存到位）→ 发券商 → 写审计 → 清标记；崩溃凭订单编号精确恢复，不重复下单；账实不符自动紧急停止留证；终态恢复优先于当前策略。
8. **人工批准转发**：拒绝/超时/连接错误一律不下单；审批编号采用固定格式前缀，防止审批错乱导致重复下单。
9. **券商三层档案**：纸面只读、实盘只读、实盘交易（须过门禁）；七家纸面封顶券商在入口拒绝真实配置；三家完全只读券商无下单能力；模拟器只认自己签发的订单号。
10. **审计**：只增台账、逐条密封链接、断链拒写、写入即保存到位、支持离线自包含核验与分段密封。

| 结论结构化展示 | 快照中点击任一角色或最终决策查看结论时，标题层级、段落、有序/无序列表、表格、加粗/斜体等重点标注按业务文档结构渲染；残缺不齐、无法成表的内容该段降级为纯文本原样展示，不丢字、不影响同篇其他内容 |
| 沿用编队纪律 | 发起后的评估沿用编队既有规则（统一基准事实、成果未达标判定、取消、退避重试、审核熔断、用量红线等，见 4.7） |
| 评估留存 | 调整后的流程图（含各角色职责、可用分析能力、使用技能、执行时长与连线）、各角色过程与结论、最终决策、标的、问题、终态与发起时间以评估快照长期留存、不自动清理；仅发起本人可见；快照在发起时即独立完整，自定义团队事后修改或删除不影响任何历史快照 |

### 4.10 角色广场与角色准入规则（M13）

| 规则项 | 业务口径 |
| --- | --- |
| 入口与定位 | 左侧菜单栏新增"智能体（角色）"页面，全员可进入；该页面是系统内创建、查看、单独运行与管理角色的唯一入口；团队编排画布不再承担创建角色职能 |
| 分组展示 | 内置角色：按内置团队预设分组，每组列出该预设的全部角色，卡片含名称、业务用途简介与已通过标识；自建角色：单设"自建角色"分组；每个分组提供搜索框，按角色名称关键字在组内检索，清空即恢复组内全部 |
| 内置角色口径 | 全部内置角色默认"已通过"，内容（职责提示词、工具、技能、可用分析能力）只读、不可改不可删；对全员可见，可单独运行、可在画布引入 |
| 新建角色 | 支持两种起步方式：从空白创建，或选择角色广场中任一"已通过"角色（内置角色或已通过的自建角色）作为模板派生；选中模板后业务用途、职责提示词、可用分析能力、工具、使用技能与执行时长自动预填、可再修改，角色名称不预填、必须重新填写且全局唯一；未通过角色不得作为模板；派生角色初始仍为"未通过"、仅创建者可见，并登记派生来源（留痕）；保存时模板须仍为已通过、仍存在，否则拦截并提示重新选择；派生完成后角色独立，模板事后被编辑、取消通过或删除均不影响已生成角色；其余必备要素与校验同空白创建 |
| 名称唯一性 | 角色名称在全系统范围内全局唯一（含内置角色）；重名一律拦截并提示改名，不自动覆盖、不自动追加后缀 |
| 未通过可见性 | 新建角色初始为"未通过"，仅创建者本人可在"自建角色"分组查看、打开、单独运行与管理；其他投资者在任何分组均不可见 |
| 详情页结构 | 三个页签："角色档案"（业务用途、职责提示词全文、工具清单、技能清单、可用分析能力，只读展示，每项工具/技能附业务用途说明）、"单独运行"（填写评估标的与研究问题发起并查看本次结论）、"评估历史"（本人对该角色的运行记录列表，可打开结论） |
| 单独运行 | 输入与团队评估一致：评估标的（代码或名称）与研究问题，任一为空不得发起；不组建团队、仅该角色独立开展一次研究；成果合格口径沿用编队成果未达标判定——空稿、只列计划、模拟数据均判未成功；一次运行对应一条历史记录 |
| 评估历史可见性 | "评估历史"页签仅展示查看者本人对该角色的运行记录（发起时间、标的、研究问题、终态与结论）；不同投资者互不可见；历史结论按业务文档结构化呈现，残缺不成表部分降级为纯文本 |
| 放开通过前置 | 角色至少由任一投资者成功单独运行一次并产出合格结论后，运维管理员详情页才出现"放开通过"操作；此前管理员也无法放行，页面明示所缺条件 |
| 管理员审核视角 | 审核场景下，运维管理员可查看该角色下全部人员的单独运行记录与结论，作为放行依据；该查看权限仅管理员具备 |
| 放开通过效力 | 管理员放开通过后，角色对所有投资者可见，立即出现在团队编排画布"新增角色"可选清单中；通过状态为全局状态，对所有投资者一致 |
| 创建者维护权 | 创建者可随时编辑自己的角色（名称除外的全部要素；名称修改仍须满足全局唯一），角色已通过也可编辑、编辑后保持已通过状态、无需重新审核；删除角色须二次确认；删除即退出编排可选清单；非创建者（不含管理员的准入操作）无编辑删除入口 |
| 取消通过 | 运维管理员可对已通过角色随时"取消通过"；取消后角色立即退出画布"新增角色"清单，且对非创建者不再可见；创建者仍可在"自建角色"分组查看与再次单独运行，后续可重新放开通过 |
| 失效引用处理 | 角色被取消通过或删除后，已保存自定义团队载入时该角色节点以失效引用高亮并说明原因，替换或移除前不得发起评估；已留存的团队评估快照、角色单独运行记录与结论均原样保留、可完整回看 |

### 4.11 技能广场与技能准入规则（M14）

| 规则项 | 业务口径 |
| --- | --- |
| 入口与定位 | 左侧菜单栏新增与"智能体团队编排""智能体（角色）"并列的"技能广场"页面，全员可进入；该页面是系统内浏览、查看、单独试运行、创建维护技能与办理技能准入的唯一入口；编排页内不再保留技能广场页签，也不提供任何技能试运行或技能包导入入口 |
| 页面结构 | 页面顶部设"技能广场"与"我的评估"两个页签；"技能广场"页签分"内置技能"与"自建技能"两个分组，每组提供搜索框按技能名称关键字组内检索、清空即恢复；"我的评估"页签跨技能汇总本人全部试运行记录 |
| 技能来源与分组 | 内置技能分组：系统内置技能与运维管理员全局装配（手动导入、一键同步）的技能，对全员可见；自建技能分组：仅展示查看者本人创建（空白创建、另存派生、zip 导入）的技能，未通过的他人自建技能任何人都看不到 |
| 内置技能口径 | 内置技能内容（业务用途简介、方法论与操作说明、输入要求、输出约定）只读、不可改不可删；全员可查看、可试运行、可"另存为新建技能" |
| 技能业务要素 | 技能名称、业务用途简介、方法论与操作说明（全文）、输入要求（运行所需标的与信息）、输出约定（产出结论的结构）；五项均为创建/另存时的登记要素，方法论与操作说明等必备项为空时拦截保存并逐项提示 |
| 名称唯一性 | 技能名称在全系统范围内全局唯一（含内置技能与管理员装配技能）；重名一律拦截并提示改名，不自动覆盖、不自动追加后缀 |
| 新建技能 | 全员可从空白创建技能；保存后技能以"未通过"状态进入本人"自建技能"分组，仅创建者可见、可试运行、可管理 |
| 另存为新建技能 | 任一"已通过"技能（内置技能、管理员全局装配且已通过的技能、已通过的自建技能）均可作为模板；选中后业务用途简介、方法论与操作说明、输入要求、输出约定自动预填、可再修改，名称不预填、必须重新填写且全局唯一；未通过技能不具备模板资格；保存时模板须仍存在且仍为已通过，否则拦截并提示重新选择；派生完成后技能独立，模板事后被编辑、取消通过或删除均不影响已生成技能；派生来源在技能档案中登记留痕 |
| 导入 zip 技能包（全员·预留） | 技能广场为全员提供"导入 zip 技能包"入口（预留能力）：导入成功后技能以"未通过"状态归入导入者本人"自建技能"分组，仅本人可见，后续试运行与审核准入口径与空白创建技能完全一致；与金融无关或要素不完整的包在导入环节即拒绝并逐项说明原因 |
| 详情页结构 | 三个页签："技能档案"（五项业务要素只读展示；自建技能在创建者视角可切换编辑；派生技能另展示派生来源）、"试运行"（填写评估标的与研究问题发起并查看本次结论）、"试运行历史"（本人对该技能的试运行记录列表，可打开结论） |
| 单独试运行 | 输入评估标的（代码或名称）与研究问题，任一为空不得发起；不组建团队、不配置角色，仅该技能独立开展一次评估；成果合格口径沿用编队成果未达标判定——空稿、只列计划、模拟数据均判未成功；一次试运行对应一条历史记录 |
| 试运行历史可见性 | 技能详情"试运行历史"与"我的评估"页签均仅展示查看者本人的记录（技能名、发起时间、标的、研究问题、终态与结论）；不同投资者互不可见；结论按业务文档结构化呈现，残缺不成表部分降级为纯文本 |
| 我的评估筛选 | 支持按技能名、评估标的关键字（代码或名称片段，模糊匹配）与发起时间起止日期区间（含起止当日）筛选；三个条件可单用、可组合，清空后恢复全部本人记录 |
| 自建技能放开通过前置 | 自建技能（含 zip 导入技能）至少由任一投资者成功试运行一次并产出合格结论后，运维管理员详情页才出现"放开通过"操作；此前管理员也无法放行，页面明示所缺条件 |
| 管理员审核视角 | 审核场景下，运维管理员可查看该自建技能下全部人员的试运行记录与结论作为放行依据；该查看权限仅管理员具备 |
| 自建技能放开通过效力 | 管理员放开通过后，技能对所有投资者可见，立即出现在角色配置与团队编排画布"新增技能"可选清单中；通过状态为全局状态，对所有投资者一致 |
| 全局技能准入（管理员装配） | 运维管理员经管理员专区手动导入第三方金融技能包或一键同步装配的技能为全局技能：任一次试运行产出合格结论即全局标记"已通过"并对所有人生效，无需另行审核；通过后再次试运行失败不撤销通过状态，仅记发起者本人历史；新装配技能一律未通过；更新版本保留原通过状态；来源下架技能退出可选清单；与金融无关或要素不完整的包在装配环节拒绝 |
| 两类导入的区分 | 全员"导入 zip 技能包"产生仅本人可见的未通过自建技能、须经管理员审核放开通过；管理员专区的"导入第三方金融技能包/一键同步"产生面向全员的全局技能、试运行成功即自动全局通过；管理员专区仅运维管理员可见，普通投资者页面不出现该专区 |
| 创建者维护权 | 创建者可随时编辑自己的技能（名称修改仍须全局唯一），技能已通过也可编辑、编辑后保持已通过状态、无需重新审核；删除技能须二次确认，删除即退出角色配置与编排可选清单；非创建者（不含管理员准入操作）无编辑删除入口；内置技能不可编辑、不可删除 |
| 取消通过 | 运维管理员可对已通过的自建技能随时"取消通过"；取消后技能立即退出角色配置与编排可选清单，且对非创建者不再可见；创建者仍可在本人"自建技能"分组查看与再次试运行，后续可重新放开通过 |
| 失效技能引用 | 技能被取消通过、删除或来源下架后，已保存角色配置与自定义团队载入时该技能以失效引用高亮并说明原因，替换或移除前不得发起评估；管理员装配的全局技能下架不影响其已留存快照；已留存的团队评估快照、技能试运行记录与结论均原样保留、可完整回看 |

## 6. Data and Permission Rules（数据与权限规则）

### 6.1 数据留存与归档

| 数据类别 | 留存与归档规则 |
| --- | --- |
| 会话与研究记录 | 每场研究全过程留痕，长文外置不截断；记录一次性完整写入并确保保存到位；单条损坏记录跳过、不影响其他会话；支持跨会话全文检索；时间一律标注时区 |
| 研究卡片 | 每次回放产出结构化版与阅读版两份；异常数值（空值、无穷）写空；密钥不入卡；内容审核警告原样保留；含配置与策略特征印记以便复现 |
| 运行产物 | 每场研究独立运行资料区（思考、产物、研究记事、用量账）；编队另有独立编队资料区与每角色工作区，越界写入拒绝 |
| 用量账 | 逐场、逐角色、逐次记录供应方、模型、输入/输出/总用量、调用次数与逐轮明细，按世界标准时间记账 |
| 审计台账 | 只增不改；逐条密封链接；断链拒写；写入即保存到位；支持离线自包含核验与分段轮转密封（整段删除亦可检出） |
| 每日下单计数 | 按世界标准时间自然日、多份运行并发也加锁、按动作编号去重；计数档案损坏则拒绝记账；日切清零 |
| 授权书凭证 | 不可变只读凭证；助手无创建/修改通道；含批准凭证密押、券商、不透明账户标识与到期日；损坏或未知版本按无授权处理 |
| 策略证据 | 证据记录生成后不可修改；重建整体替换；按"策略＋市场环境"为键；含空缺或非法分类词的记录拒绝写入/读取时丢弃告警 |
| 交易与组合数据 | 持仓快照保留"上次成功时间"；对账报告区分金额漂移、结构差异、品种多缺三类；不完整或过期快照不可对账 |
| 影子账户数据 | 证据工件确定性可复现、只追加；暂存按"模型+时间窗+流水特征印记"三匹配；被排除币种须显式披露笔数与币种 |
| 定时研报外发记录 | 外发箱记录长期留存；认领租约 5 分钟；同一封只发一次；研究失败投递终止；错误信息擦去密钥与本机位置、限 1000 字符 |
| 渠道配置 | 未知字段拒绝；空密码=保留旧密码；坏凭证不保存；凭据登记仅本人可读写；任务档案仅本人可读写 |
| 自有行情库 | 用户主目录下的本地行情仓库；默认关闭网络暂存；数据写入位置不得因配置错误漂移到工作目录 |
| 记忆数据 | 分"本人记忆"与"本项目记忆"两类；支持遗忘（删除）、回收清理；丢失标识的条目可找回但不覆盖较新内容；交易前建议默认仅观察、不自动行动 |
| 试验数据 | 验收试验中的全部数据写入试验沙盒，触碰真实家目录或真实审计账即判验收失败 |
| 团队评估快照 | 每次网页团队评估保存一份完整只读快照：发起时的协作流程图（角色名称、职责说明、可用分析能力、使用技能、执行时长与连线依赖）、评估标的与研究问题、各角色分析过程与结论、最终决策结论、终态与发起时间；长期保留、不自动清理；仅发起本人可见，用户之间互不可见；不主动另存即不生成团队方案，内置预设不被修改；快照在发起时即独立完整，其依据的自定义团队事后被修改或删除均不改变任何已留存快照 |
| 自定义团队 | 投资者在画布上主动"另存为我的团队"生成的个人团队定义（角色、连线、职责、能力、技能、时长、名称、简介）；仅本人可见、可用、可管理（原地更新/另存副本/删除）；长期保留、不自动清理，仅本人可手动删除；删除不影响历史评估快照；内置预设不被自定义团队改动 |
| 技能试运行记录 | 投资者在技能广场对单个技能发起试运行的历史：技能、评估标的、研究问题、发起人、发起时间、终态与结论；长期保留、不自动清理；技能详情"试运行历史"与"我的评估"页签均仅发起本人可见，其他投资者互不可见，运维管理员为审核放行自建技能可查看该技能全部人员的记录；记录同时支撑技能广场"我的评估"跨技能汇总（按技能名、标的关键字与发起时间区间筛选）；技能被取消通过或删除后记录仍完整保留；通过状态为全局共享，不随试运行记录归属隔离 |
| 技能包与技能通过状态 | 已装配全局技能（内置、管理员手动导入第三方金融技能包与一键同步）以技能名称、业务用途简介、方法论与操作说明、输入要求、输出约定登记；管理员装配技能的通过状态全局唯一、对所有投资者一致：任一次试运行成功即标记通过，失败不撤销，同步更新版本保留状态，下架退出可选清单；装配环节拒绝与金融无关或要素不完整的包 |
| 自建技能 | 投资者从空白创建、以已通过技能"另存为新建"派生或经全员"导入 zip 技能包"（预留）导入的个人技能：以技能名称（全局唯一、重名拦截）、业务用途简介、方法论与操作说明、输入要求、输出约定登记，并登记创建者与派生来源；初始"未通过"、仅创建者可见、可试运行与维护；至少一次合格试运行后经运维管理员放开通过方全员可见、可在角色配置与编排画布勾选；创建者可随时编辑（通过后编辑不撤销状态）、删除须二次确认；管理员可取消通过；取消通过或删除后退出可选清单、已保存角色与团队中的引用失效高亮，历史快照与试运行记录不受影响 |

| 角色单独运行记录 | 投资者在角色详情页对单个角色发起单独运行的历史：角色、评估标的、研究问题、发起人、发起时间、终态与结论；长期保留、不自动清理；仅发起人本人可在该角色"评估历史"查看，其他投资者互不可见；运维管理员为审核放行可查看该角色全部人员的记录；角色被取消通过或删除后记录仍完整保留 |

### 6.2 访问权限范围

1. **研究权限（默认全员）**：所有行情、资料、回放、因子、组合只读分析能力开箱可用，不需要交易授权。
2. **真实交易权限（最小授权）**：仅在授权书有效期内、逐笔受七步门禁约束；默认只读、默认只撤挂单；外汇需品种+市场桶双放行；黑名单不可覆盖。
3. **账户绑定权限**：多账户登录时，订单只准发往授权书绑定的唯一账户，全程不回退默认账户。
4. **渠道操作员权限**：分全局操作员与单渠道操作员，二者隔离；零操作员时所有配对请求默认全拒；群内管理指令按发令个人授权。
5. **编队能力准入**：编队可访问的外部数据能力以运维预先批准为准；研究主题文本不能授予新能力，未批准能力装配时剔除告警。
6. **远程访问权限**：系统默认只接受本机访问；非本机访问必须设置访问密钥；密钥一经设置，本机请求同样须出示；实时访问票据一次性、不可重放。
7. **资料访问范围**：研究工具与渠道附件只能读写允许的运行根目录、渠道专属资料区与记忆专属资料区；穿越、越界、跨网共享位置一律拒绝。
8. **四眼原则**：策略作者与批准人不得为同一人（当前为提示性约束，不阻断登记）「【逆向推断·待业务复核】」。
9. **编队编排权限（全员开放）**：所有投资者均可选用全部内置团队预设与本人的自定义团队；画布新增角色只能从角色广场全部已通过角色中引入（画布不提供创建入口），引入后可在画布临时调整职责说明、使用技能与执行时长且不回写角色本体，未主动另存的调整仅对本次评估生效，不改变内置预设；主动另存的自定义团队仅本人可见、可用、可管理（更新/另存/删除），其他投资者不可见；角色可勾选的分析能力以该团队允许的能力目录为边界、目录外能力不可自行加入；角色"使用技能"默认取团队预设技能并集，经"新增"仅可勾选全局已通过的技能；团队评估记录仅发起本人可见。
10. **技能广场权限（全员开放）**：所有投资者均可从左侧菜单进入独立的"技能广场"页面（编排页内不再设技能广场页签），浏览"内置技能"分组全部已装配技能及其全局通过状态、查看技能详情五项业务要素、以评估标的与研究问题对单个技能发起试运行、在技能详情"试运行历史"与跨技能"我的评估"页签查看仅本人的试运行记录（支持按技能名、标的关键字与发起时间区间筛选）；所有投资者均可从空白创建技能、以任一已通过技能为模板"另存为新建技能"、经"导入 zip 技能包"（预留）导入外部技能为本人未通过自建技能，并可随时编辑本人技能（通过后编辑不撤销通过）、二次确认后删除本人技能；未通过自建技能仅创建者本人可见、可试运行、可管理，内置技能只读不可改删；技能通过状态全局共享。
11. **全局技能包引入权限（仅运维管理员）**：技能广场管理员专区的"导入第三方金融技能包"与"一键自动同步金融相关技能"仅运维管理员可操作，普通投资者页面不展示该专区；管理员装配的是面向全员的全局技能，新装一律未通过、任一次试运行成功即自动全局通过，更新版本保留原通过状态，下架退出可选清单；非金融或要素不完整的包装配时拒绝。全员"导入 zip 技能包"产生的是仅本人可见的自建技能，与本项管理员专区相互独立。
12. **角色广场权限（全员开放）**：所有投资者均可从左侧菜单进入"智能体（角色）"页，浏览全部已通过角色（内置角色按团队预设分组展示、内容只读）、从空白创建本人角色、在角色详情页查看提示词/工具/技能档案、以评估标的与研究问题单独运行任一可见角色、查看本人的角色评估历史；未通过角色仅创建者本人可见、可运行、可管理；创建者可随时编辑自己的角色（通过后编辑不撤销通过）、删除须二次确认。
13. **角色准入权限（仅运维管理员）**：角色"放开通过"与"取消通过"仅运维管理员可在角色详情页操作；放开通过以该角色至少一次合格的单独运行为硬性前置，无合格记录时操作不可用；审核时管理员可查看该角色下全部人员的单独运行记录与结论；取消通过后角色退出编排可选清单，已保存团队中的引用失效高亮、校正前不得发起，历史快照与运行记录保留。
14. **自建技能准入权限（仅运维管理员）**：自建技能（空白创建、另存派生、zip 导入）的"放开通过"与"取消通过"仅运维管理员可在技能详情页操作；放开通过以该技能至少一次合格的试运行为硬性前置，无合格记录时操作不可用；审核时管理员可查看该技能下全部人员的试运行记录与结论；放开通过后技能对全员可见并进入角色配置与编排画布"新增技能"清单；取消通过后技能退出可选清单、对非创建者不可见，已保存角色与团队中的引用失效高亮、校正前不得发起，历史快照与试运行记录保留；管理员全局装配技能不适用本审核流程，沿用"试运行成功即全局通过"。

### 6.3 数据保密与脱敏

- **必须遮蔽**：各类访问凭据与密钥、访问票据、密码/口令、请求附带的鉴权信息、运行设置、账户号码、路由号码、社会保障号/税务号、账户内部编号与链接、中转地址中的账号口令。
- **刻意保留**：标的代码、买卖数量、订单编号、订单状态，以及授权书引用、同意记录引用、不透明账户引用——以维持"谁点击授权→哪份授权书→哪笔订单"的完整责任链。
- **脱敏时机**：留存、实时推送、外部通知三个出口之前统一脱敏，三处拿到同一份结果；植入密钥不得进入长期留痕与事件预览。
- **展示规则**：密钥字段 8 字符及以内全遮，9 字符以上仅露最后 4 位；计数类文本（如用量计量中的数字）保持可读。
- **上传与外发**：可执行及与系统安装相邻的类型拒收；附件按渠道/发送人隔离；外部链接禁止指向本机、内网与云凭证地址；云端识别资料须用户显式选择。

| 券商档案 | 同一家券商的三类接入身份：纸面只读、实盘只读、实盘交易。 |
| 总敞口 | 多头与空头市值之和，不做净值抵消；从零仓卖出按新增空头敞口计。 |
| 人工批准转发 | 每一笔订单先送人工审批，批准后才转发券商；拒绝或超时即不下单。 |
| 编队 | 由多个研究角色组成、按任务依赖协作的虚拟投研团队（如投资委员会）。 |
| 预设编队 | 预置好角色分工的编队模板，共 30 套；可点名或按研究主题匹配。 |
| 编队主持人 | 负责匹配编队、统一基准、派活、门禁与归集报告的调度角色。 |
| 未达标 | 角色成果不合格的统称：空稿、只写计划、声称模拟数据、原始返回当分析等。 |
| 受阻 | 因前置任务未成功而不得开工的后置任务状态。 |
| 续跑 | 失败编队重跑时沿用未变任务结论、仅重算失败部分的复盘方式。 |
| 研究目标 | 承载复杂课题的容器，有 12 种状态、预算与最多 3 次自动续作。 |
| 假设 | 待检验的投资想法，状态只能沿"探索中→验证中→已验证"推进。 |
| 无进展守护 | 研究反复失败或反复复读同一结果时，按既定轮次上限主动终止研究的守护纪律。 |

| 心跳 | 编队角色与定时任务定期上报的"仍在工作"信号；失联达到时限即被回收为终态。 |
| 前视探针 | 因子审查手段：故意改动探针日之后的数据，若探针日的因子值随之改变即判定偷看未来。 |
| 样本外 | 专门留出来、建模阶段完全不许看的一段历史，用于检验策略是否只在旧数据上有效。 |
| 影子盘 | 不下真实订单、仅用真实行情模拟记录策略表现的对照阶段，是六阶段之一。 |
| 市场大类 | 授权书对可交易板块的分组许可（如外汇须品种与市场桶双放行）。 |
| 小仓实盘金丝雀 | 策略证据流水线最后阶段：以最小真实仓位验证策略的安排。 |
| 衰减 / 失效 | 策略证据随时间老化：90 天老化转观察，180 天失效转停用。 |
| 再平衡容差带 | 权重偏离目标不超过该带时不调仓，避免频繁折腾；真实目标改变时无视带宽。 |
| 遮蔽日 | 禁止调仓的指定日期；当日即使目标变为零也不卖出。 |
| 风险 X 光 | 集中度、回撤、风险价值、条件期望损失、贝塔、相关性等一揽子风险透视。 |
| 归因桶 | 影子账户盈亏归因的互斥分类：错过的信号、噪声交易、过早止盈、过晚止损、过度交易。 |
| 本福特法则 | 通过数字首位分布识别财务数据是否异常的验真方法；样本不足 50 不可信。 |
| 希腊字母 | 期权价格对各风险要素敏感度的统称（Delta 等）。 |
| 保证金 / 强平 / 资金费 | 杠杆交易的担保资金、担保不足时被强制了结、持仓周期性费用。 |
| 外发箱 | 定时研报投递长期留存的记录：同一封只发一次、崩溃可补发、失败有限重试。 |
| 配对码 | 陌生聊天使用者私聊机器人时获得、须经登记操作员批准的授权凭据。 |
| 礼貌间隔 | 为保护免费公共行情服务、对同一供应方两次请求之间的最小间距（含随机抖动）。 |
| 时点数据 | 财报等数据只能在其"实际披露日之后"才可见的纪律，防止未来信息泄漏。 |
| 世界标准时间 | 跨地区统一的计时口径；每日下单笔数按此日切。 |
| 团队预设 | 预先配置好角色分工与协作顺序的内置智能体团队模板（如投资委员会）；编排页集中展示全部预设，预设本身不可被用户改动。 |
| 编排画布 | 以流程图形式调整团队角色与协作关系的网页操作区：角色为节点、角色间的上下游交接关系为连线。 |
| 角色节点 | 流程图中承担特定职责的一个研究岗位；要素含角色名称、职责说明、可用分析能力、使用技能与执行时长。 |
| 可用分析能力 | 角色在本次评估中被允许使用的研究手段清单；只能在该团队预设允许的能力目录内勾选，不可自行填入目录外能力；该边界不受"使用技能"设置影响。 |
