## 一、史诗故事

### 1.1 宏观业务目标

在 Vibe-Trading 左侧菜单栏新增「投资名人」入口，点击后进入一个**投资大佬持仓 & 言论跟踪**Web 单页应用。页面以 **Tab 形式**组织内容，包含两个 Tab：「投资人详情」与「名人周动态」。页面面向**个人散户投资者**，核心业务目标有二：

1. **追踪与核验**：聚合各位头部投资人的公开持仓、公开发言与调仓动向，并提供「复查」能力核验信息真实性，客观展示，不构成投资建议；
2. **辅助决策参考**：帮助散户投资者了解大佬的最新动向与历史观点，作为自身投资决策的参考信息来源。

页面整体风格：简洁专业、偏金融数据看板，文字清晰、表格整齐，不使用花哨动画。

### 1.2 项目模块规划

| 模块 | 说明 |
| --- | --- |
| Tab 导航 | 页面顶部 Tab 切换：「投资人详情」「名人周动态」「公募持仓」 |
| 投资人详情 Tab | 下拉切换投资人，展示单投资人卡片全套数据（持仓、观点、调仓、绩效等） |
| 名人周动态 Tab | 居中汇聚所有投资人的周动态，按「人名 + 内容」聚合展示 |
| 公募持仓 Tab | 以标的为第一维度聚合所有投资人的当前持仓，展示持有机构、调仓动作、持有次数、建仓价/最新价；支持批量更新价格；底部展示最近一批次清仓标的 |
| 投资人切换与管理 | 下拉切换预置投资人；支持手动新增/删除投资人 |
| 投资人卡片 | 展示名称、投资风格、客观绩效评价、当前持仓、最新观点、历史观点、最新调仓动向 |
| 持仓快照查看 | 当前持仓区块提供「查看历史快照」入口，按日期倒序展示 `vibe.celebrity_position_snapshot` 中该投资人的历史持仓快照 |
| 数据刷新 | ~~定时每周日凌晨 4 点批量刷新全部投资人~~（**已废弃**：本工程不再内置定时调度，改由 Trae 工作台定时任务调用最新动态接口批量刷新）；右下角悬浮刷新按钮手动刷新当前投资人 |
| 历史回灌 | 针对当前投资人，拉取其历史持仓与观点并按时间线追加 |
| 复查核验 | 多选历史观点 / 调仓记录，提交大模型核验，回填置信度与事后评判 |
| 提示词管理 | 各功能按钮旁支持查看与编辑对应提示词，即时生效 |

### 1.3 核心业务流程

```
用户点击左侧菜单「投资名人」
   │
   ├─ 进入页面，默认展示「投资人详情」Tab
   │     │
   │     ├─ 下拉选择投资人 ──► 加载该投资人卡片全套数据
   │     ├─ 手动刷新（悬浮按钮）──► 拉取该投资人最新持仓+言论+调仓 ──► 持仓覆盖+变动快照、观点/调仓追加
   │     ├─ 历史回灌（按钮）────► 拉取该投资人历史持仓+观点 ──► 持仓入快照表、观点追加
   │     ├─ 绩效评价（按钮）────► 获取/手动填写客观绩效评价
   │     └─ 复查（多选条目+按钮）► 核验观点/调仓真实性 ──► 回填置信度、事后评判、收益
   │
   └─ 切换至「名人周动态」Tab
         │
         └─ 居中汇聚所有投资人的周动态，按「人名 + 内容」展示

   └─ 切换至「公募持仓」Tab
         │
         ├─ 以标的为维度聚合所有投资人当前持仓
         ├─ 每行展示：标的名称、持有机构及动作、持有次数、建仓价、最新价
         ├─ 「更新全部价格」按钮 ──► 批量查询所有标的最新价
         └─ 底部展示最近一批次清仓的标的信息
```

## 二、用户故事

### US-00：Tab 页面切换

**作为**个人散户投资者，
**我想要**在「投资人详情」与「名人周动态」两个 Tab 之间切换，
**以便于**在单投资人深度视图与全市场名人周动态聚合视图之间灵活切换。

#### 验收用例

```gherkin
Feature: Tab 导航

  Scenario: 默认进入投资人详情 Tab
    Given 用户点击左侧菜单「投资名人」
    When 页面加载完成
    Then 默认展示「投资人详情」Tab
    And 页面顶部显示两个 Tab：「投资人详情」「名人周动态」
    And 「投资人详情」处于选中状态

  Scenario: 切换至名人周动态 Tab
    Given 用户当前在「投资人详情」Tab
    When 用户点击「名人周动态」Tab
    Then 页面展示名人周动态聚合视图
    And 「投资人详情」Tab 的状态不丢失（切回时保留原选择）

  Scenario: 切回投资人详情 Tab 保留状态
    Given 用户在「投资人详情」Tab 选择了「冯柳」
    And 用户切换至「名人周动态」Tab
    When 用户切回「投资人详情」Tab
    Then 仍展示「冯柳」的卡片数据
```

### US-03：手动刷新当前投资人数据

**作为**个人散户投资者，
**我想要**点击右下角悬浮刷新按钮，
**以便于**手动触发拉取该投资人的最新持仓、言论与调仓动向。

#### 验收用例

```gherkin
Feature: 手动刷新

  Scenario: 悬浮刷新按钮位置
    Given 用户在投资人卡片页面
    Then 页面右下角存在悬浮刷新按钮
    And 按钮不遮挡页面正文内容

  Scenario: 点击刷新成功
    Given 用户选择了投资人「冯柳」
    When 用户点击悬浮刷新按钮
    Then 页面弹出提示「开始拉取大模型最新持仓言论」
    And 页面显示加载状态
    When 大模型返回有效数据
    Then 当前持仓直接覆盖旧持仓（不追加）
    And 若新旧持仓有变动，则保存一份带日期标签的持仓快照；无变动则快照不动

    And 页面提示刷新成功
    And 每条新增数据带有本次更新时间戳

  Scenario: 刷新返回空数据
    Given 用户选择了某投资人
    When 用户点击刷新按钮
    And 大模型返回无新公开信息
    Then 保留该投资人原有数据不变
    And 页面提示「暂无新公开信息」

  Scenario: 刷新失败
    Given 用户选择了某投资人
    When 用户点击刷新按钮
    And 大模型返回失败/超时
    Then 页面提示刷新失败
    And 原有数据保持不变
    And 用户可重新点击刷新重试
```

### US-04：定时自动刷新全部投资人（已废弃，改由 Trae 工作台实现）

> **状态：已废弃。** 本工程不再内置定时调度任务。定时批量刷新改由 **Trae 工作台定时任务**调用 `/api/celebrity/investors/{id}/refresh` 接口（或批量接口）实现，复用「最新动态提示词」（A.1）。下方验收用例保留作为 Trae 工作台定时任务的行为参考。

**作为**个人散户投资者，
**我想要**系统每周日凌晨 4 点自动刷新全部投资人的数据，
**以便于**无需手动操作即可保持数据时效性。

#### 验收用例

```gherkin
Feature: 定时自动刷新

  Scenario: 每周日凌晨 4 点触发刷新
    Given 系统到达每周日凌晨 4:00
    When 定时任务触发
    Then 系统逐个调用「最新动态」获取每位投资人的最新持仓+言论+调仓
    And 每位投资人的当前持仓直接覆盖；若仓位变动则保存带日期标签的持仓快照
    And 观点、调仓动向按时间线追加，不覆盖旧数据
    And 刷新结果（成功/失败/无新信息）记录在案

  Scenario: 刷新过程不影响用户当前查看
    Given 定时任务正在后台刷新
    When 用户正在查看某投资人卡片
    Then 用户当前视图不被打断
    And 刷新完成后用户切换或刷新页面可看到新数据
```

### US-05：复查历史观点

**作为**个人散户投资者，
**我想要**勾选一条或多条历史观点并点击「复查」，
**以便于**核验观点真实性并获取置信度与事后评判。

#### 验收用例

```gherkin
Feature: 历史观点复查

  Scenario: 勾选多条观点并复查
    Given 用户正在查看某投资人的历史观点列表
    When 用户勾选 2 条历史观点
    And 用户点击「复查」按钮
    Then 系统将勾选的观点（包含发布时间、观点原文）提交核验
    And 核验完成后自动回填对应条目的「置信度」与「事后评判」字段

  Scenario: 置信度等级
    Given 复查返回结果
    Then 置信度取值为：高（本人公开原话、正式访谈/公告）
    或 中（权威媒体转述，有间接证据）
    或 低（自媒体传言、断章取义、找不到原始出处）
    或 无效（伪造言论）

  Scenario: 事后评判内容
    Given 复查返回结果
    Then 事后评判包含两点：
      ① 该言论是否真实为该投资人所说
      ② 事后市场/标的走势是否印证该判断，客观描述，控制在 80 字以内

  Scenario: 复查失败
    Given 用户勾选了若干历史观点
    When 用户点击「复查」
    And 核验返回失败/超时
    Then 页面提示复查失败
    And 已勾选条目的置信度与事后评判保持不变
    And 用户可重新点击复查重试
```

### US-06：复查调仓动向

**作为**个人散户投资者，
**我想要**勾选一条或多条调仓记录并点击「复查」，
**以便于**核验调仓真实性并补充账面收益与事后评判。

#### 验收用例

```gherkin
Feature: 调仓动向复查

  Scenario: 勾选多条调仓记录并复查
    Given 用户正在查看某投资人的调仓动向列表
    When 用户勾选 2 条调仓记录
    And 用户点击「复查」按钮
    Then 系统将勾选的调仓记录（包含时间、动作、标的）提交核验
    And 核验完成后自动回填对应条目的「账面收益」与「事后评判」字段

  Scenario: 账面收益描述
    Given 复查返回结果
    Then 账面收益描述为：该次调仓后对应标的从调仓时间至今的区间涨跌幅
    And 收益仅基于公开二级市场行情，不估算大佬个人实际盈亏
    And 无公开行情时填写「无法获取」

  Scenario: 调仓事后评判内容
    Given 复查返回结果
    Then 事后评判包含两点：
      ① 本次调仓记录是否属实
      ② 事后标的走势，客观描述，80 字以内，不构成投资建议

  Scenario: 私募非公开调仓处理
    Given 某调仓记录无法确认真实性
    Then 标注该记录真实性存疑
    And 不估算收益
```


## 三、业务规则

### 3.1 数据管理规则

| 规则 | 说明 |
| --- | --- |
| 当前持仓写入策略 | 当前持仓采用**覆盖式**写入：每次刷新先删除该投资人旧持仓，再写入新持仓（前 15 大重仓），不按时间线追加 |
| 持仓快照策略 | 刷新时若新旧持仓有变动（标的集合或持仓占比不同），则将旧持仓整体写入持仓快照表 `vibe.celebrity_position_snapshot`，以**日期**作为快照标签；无变动则快照不动 |
| 历史持仓写入策略 | 历史回灌的持仓数据写入**持仓快照表**（带日期标签），不覆盖当前持仓 |
| 观点/调仓写入策略 | 最新观点、历史观点、调仓动向**按时间线追加**，不覆盖旧数据 |
| 数据去重 | 同一投资人同一时间同一标的/同一观点的重复记录，不重复追加；持仓快照同日允许多份 |
| 持仓快照查看 | 当前持仓区块提供「查看历史快照」入口，按日期倒序展示 `vibe.celebrity_position_snapshot` 中该投资人的全部历史持仓快照；同一日期的多条记录归为同一份快照 |
| 更新时间戳 | 每条数据必须携带更新时间戳，标识该条数据的获取时间 |
| 本地留存 | 数据永久保存在本地，除非用户手动删除投资人或清除数据 |
| 单用户模式 | 单用户本地使用，无账号权限概念 |
| 数据导出 | 不提供数据导出功能 |

### 3.2 置信度等级规则

| 等级 | 判定标准 |
| --- | --- |
| 高 | 本人公开原话、正式访谈、基金公告、定期报告 |
| 中 | 权威财经媒体转述，有间接证据 |
| 低 | 自媒体传言、二手转述、断章取义、找不到原始出处 |
| 无效 | 伪造言论 |

### 3.3 信息真实性约束

- **禁止编造未公开持仓**：私募很多持仓不披露，只整理公开可查信息；
- **禁止编造未公开言论**：找不到原始出处的内容直接判定低置信或无效；
- **区分来源类型**：所有信息必须标注来源（基金季报/访谈/股东大会/自媒体/财经媒体）和时间；
- **区分信息性质**：标注【确定公开披露】【媒体转述】【网络传闻】；
- **无信息留空**：无法确认的内容字段填空字符串，不编造；
- **收益估算约束**：账面收益仅基于公开二级市场行情，不估算大佬个人实际盈亏；私募非公开调仓标注真实性存疑。

### 3.4 绩效评价硬性规则

- 无官方定期披露净值的主体（段永平、李录个人、私募单账户等），收益字段全部填「净值未披露」，不估算收益率；
- 定性描述必须客观，禁止「大神、顶级、无敌」等情绪化吹捧词汇；
- 不预测未来，所有评价基于历史公开数据；
- 数据冲突时优先采信基金管理人官方公告、定期报告，舍弃自媒体小道数据；
- 必须包含风险备注，例如「私募净值定期披露有限、个人投资者无官方净值、持仓有滞后、不代表未来收益」。

### 3.5 刷新与复查异常处理

| 场景 | 处理方式 |
| --- | --- |
| 刷新返回空数据/无新信息 | 保留原有数据，提示「暂无新公开信息」 |
| 刷新失败/超时 | 提示失败，原有数据不变，可重试 |
| 复查失败/超时 | 提示失败，已勾选条目字段不变，可重试 |
| 回灌失败/超时 | 提示失败，已有数据不变，可重试 |

### 3.6 定时任务规则（已废弃，改由 Trae 工作台实现）

> **状态：已废弃。** 本工程不再内置定时调度。以下规则迁移至 **Trae 工作台定时任务**执行，调用本工程提供的刷新接口实现批量刷新。

- ~~触发时间：每周日凌晨 4:00~~ → 由 Trae 工作台定时任务配置触发时间；
- 触发范围：全部预置 + 手动新增的投资人；
- 调用内容：逐个调用 `/api/celebrity/investors/{id}/refresh` 拉取每位投资人的最新持仓 + 言论 + 调仓动向；
- 数据写入：当前持仓覆盖式写入（变动时保存带日期标签的快照）；观点、调仓按时间线追加，不覆盖；
- 不打断用户：后台执行，不影响用户当前页面操作。

### 3.7 投资人管理规则

- 预置投资人（冯柳、段永平、巴菲特、李录、邱国鹭等）不可删除；
- 手动新增的投资人可删除，删除时一并清除其本地数据；
- 新增投资人必填：投资人名称、投资风格（经典体系介绍）、备注；
- 投资风格为人工填写文本，可编辑，不通过大模型生成。

### 3.8 名人周动态 Tab 规则

- Tab 结构：页面包含「投资人详情」「名人周动态」「公募持仓」三个 Tab，默认展示「投资人详情」；
- 聚合方式：「名人周动态」Tab 居中汇聚全部投资人的周动态，按投资人分组展示；
- 展示结构：每个分组以「人名 + 内容」展示，内容包含该投资人本周的最新观点与最新调仓动向；
- 排序规则：各投资人分组按其最新动态的更新时间倒序排列；
- 内容字段：观点展示原文 + 发布时间；调仓展示时间 + 动作 + 标的；每条标注置信度与更新时间；
- 无动态处理：某投资人本周无新公开信息时，展示「本周暂无新公开动态」，不编造；
- 跳转联动：点击分组中的投资人名称，可跳转至「投资人详情」Tab 并自动选中该投资人；
- 数据同步：刷新（手动刷新按钮 / Trae 工作台定时任务）后，「名人周动态」Tab 内容同步更新；
- 状态保留：Tab 间切换时，「投资人详情」Tab 的选中投资人状态保留。

### 3.9 公募持仓 Tab 规则

- 聚合维度：以**标的**为第一维度，将所有投资人的当前持仓按标的名称聚合；
- 标的归一化：标的名称去除首尾空格、统一简繁体后相同即视为同一标的；
- 多行合并展示：同一标的的多个持有机构**各占一行**；「标的名称」「持有次数」「最新价」「收益率」字段在该标的的多行中**纵向合并显示**；「持有机构（动作）」「建仓价」每行分别展示；
- 排序规则：默认按持有次数倒序排列，次数相同则按标的名称排序；
- 持有机构展示：每行展示一位持有该标的的投资人名称，并标注其对该标的的**最近一次调仓动作**（增持/减持/新建/清仓）；无调仓记录则动作留空；
- 持有次数：等于持有该标的的**不同投资人数量**，同一投资人多次持有只计 1 次；
- 建仓价（第一次加入价格）：标的首次进入某投资人持仓时记录，之后对该投资人不变；跨投资人各自独立记录；逐行展示对应投资人的建仓价；
- 最新价：标的当前最新价格，可通过「更新全部价格」按钮批量查询回填；无价格时显示「—」，不影响持仓展示；
- 收益率：=（最新价 - 建仓价）/ 建仓价；以带正负号的百分比展示（如 +3.2%、-5.8%），正值绿色、负值红色；建仓价或最新价缺失时显示「—」；每次更新最新价时同步重新计算并持久化；
- 批量更新价格与收益率：点击「更新全部价格」后，对当前持仓表中所有标的批量查询最新价，回填「最新价」并同步重新计算「收益率」，完成后提示成功条数；
- 定时自动更新价格与收益率：**工程内置定时调度**，每周日凌晨 4:00 自动触发「更新全部价格」，批量更新所有持仓标的的最新价与收益率（与持仓数据刷新走 Trae 工作台不同，此定时任务保留在工程内）；
- 清仓同步快照：当某投资人对某标的执行清仓时，将该标的的「第一次加入价格」「最新价格」「收益率」同步到其**最新一条**持仓快照记录，历史快照不修改；
- 最近清仓展示：Tab 底部展示**最近一批次**（最近一次刷新/回灌周期内）所有清仓标的，包含标的名称、清仓投资人、清仓动作、建仓价、最新价、收益率、清仓时间；无记录时展示「最近无清仓记录」；
- 跳转联动：点击持有机构列表中的投资人名称，可跳转至「投资人详情」Tab 并自动选中该投资人。

## 五、数据管理规则

| 规则项 | 业务策略 |
| --- | --- |
| 数据存储位置 | 单用户本地存储 |
| 留存期限 | 永久保存，除非用户主动删除投资人或清除数据 |
| 写入策略 | 当前持仓覆盖式写入（变动时保存带日期标签的快照）；历史持仓写入快照表；观点/调仓按时间线追加；重复记录去重 |
| 持仓价格字段 | 每个持仓标的记录「第一次加入价格」（首次进入持仓时写入，对该投资人不变）和「最新价格」；无价格时留空展示「—」 |
| 收益率字段 | 每个持仓标的记录「收益率」=（最新价 - 建仓价）/ 建仓价，每次更新最新价时同步重新计算并持久化；建仓价或最新价缺失时留空 |
| 清仓价格同步 | 某投资人清仓某标的时，将该标的的「第一次加入价格」「最新价格」「收益率」同步到其最新一条持仓快照记录，历史快照不修改 |
| 价格定时更新 | 工程内置定时调度，每周日凌晨 4:00 自动批量更新所有持仓标的的最新价与收益率 |
| 时间戳 | 每条数据携带更新时间戳 |
| 删除范围 | 仅手动新增的投资人可删除，删除时清除其全部本地数据；预置投资人不可删除 |
| 数据导出 | 不提供 |
| 权限模型 | 单用户，无账号权限区分；提示词可自由查看与编辑，即时生效 |

> 用途：勾选多条历史观点，点击「复查」按钮调用，核验观点真假与合理性，输出置信度 + 事后评判。
